<objective>
Generalise the GLB converter from three hand-wired models to a table of single-mesh NPC ships and prove it end to end on the Viper (DATA-10): `.dat` to GLB, PNG to WebP, alpha to emissive bake, manifest, drift gate, provenance rows and the licence notice.

Purpose: the pipeline already converts one ship; this plan extracts the generic builder and the naming rule once, on the smallest role ship, so plan 09-03 adds the other eight as table rows. Keeping the three existing GLBs byte-identical proves the refactor changed nothing.

Design (RESEARCH Patterns 1 and 2; owner: files stay flat in `public/models/` and `public/textures/`, so the writer, the drift-gate roots and the drift test harness need no change):
- `buildShipGlb(nodeName, meshName, mesh, entry)` is the old Cobra builder with its two names as parameters; `buildCobraGlb` calls it with `"cobra3"` and `"oolite_cobra3"`.
- `shipGlbFile(model)` is the one naming rule: `oolite_<name>.dat` becomes `<name>.glb`; anything else fails as a `SCHEMA` content error. Plan 09-04's record compiler imports it for the `glb` field.
- `NPC_SHIP_GLBS` lists the single-mesh NPC GLBs (code-unit sorted). Each has an explicit one-owner row in `EMITTED_ENTRIES` and an explicit one-file row in `MODEL_SOURCE_FILES` (explicit lists, both directions asserted; never inferred from the catalogue).
- Sub-entities (flashers, lasers) are not compiled (D-04): an NPC GLB has exactly one node.

Deviation from the owner's suggested four-plan split, with reason: the converter work is two plans (this one and 09-03) because together they would edit the same five source and test files twice in one context and regenerate 52 public files; splitting keeps each plan inside the context budget. NOTICE is edited here, not at the end of the phase, because provenance travels with the asset that needs it (AGENTS.md constraint 4).

Output: the generic builder and naming rule, the Viper's four public files with provenance, updated test pins, and a table-driven NPC GLB test block that plan 09-03's rows inherit.
</objective>
