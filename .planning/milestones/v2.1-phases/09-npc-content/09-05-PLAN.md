<objective>
Make the NPC models loadable on demand at runtime and prove the first-load promise in a real browser (DATA-13), then record the phase and run the phase gate.

Purpose: DATA-13 says NPC models and textures are lazily loaded outside the first-load set and the cold start stays under 9,437,184 bytes. The asset cache gains one lazy entry point that nothing calls yet (Phase 12 is the first consumer); the browser tests prove that a cold start fetches none of the nine models or their 43 textures, and that each model can be fetched and its images decoded on demand. The loader is included now, not in Phase 12, because the cache-owner rule (the cache frees what it caches) is cheaper to settle before populator pressure (RESEARCH Pattern 4).

Scope choice (recorded): no synchronous `npcModel(glb)` accessor is added; the promise from `loadNpcModel` already carries the model, and Phase 12 adds an accessor only if its render path needs one.

Gate (owner, slow machine): this is the only plan that runs `docker compose run --rm verify` (once, in Task 3), then the targeted `budget.spec.ts` and `npc-assets.spec.ts` run. `verify-full` runs only on owner request. Task 3 records the exception in Key Decisions.
