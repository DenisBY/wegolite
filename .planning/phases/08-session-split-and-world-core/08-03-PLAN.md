<objective>
Make the determinism rules of FOUND-12 mechanical: lint rejects Math.random, Date, wall-clock reads, timers, process, crypto, for..in and bare .sort() anywhere in src/sim (success criterion 3), each proven by a probe with a positive control.

Purpose: today the sim zone bans Math.random, Date.now, performance.now and `new Date`, but nothing stops `Date.UTC`, `Date()`, a for..in loop or a lexicographic `.sort()` (RESEARCH Pattern 8). The world core added by later plans iterates entities, sorts scan results and serialises records, so the bans must be in force before that code exists. Factoring the rule lists into constants lets the AI zone (plan 08-09) restate them without silently dropping them.

Output: extended eslint.config.js, a reusable probe helper, and a guard test; plus (Task 3) the entity-id scope guard.

Decision recorded here (RESEARCH A8, research refresh 92f2681 of 2026-11-12): CONTEXT D-06 as amended on 2026-11-12 says no entity id may outlive the world that issued it, so nothing outside the world (saves, HUD, probe, logs, mission state, targeting across a jump) stores or transports one. The refreshed research left open whether to enforce that mechanically (assumption A8). This plan adopts it as a source-scan guard test, tests/guards/entity-id-scope.test.ts, not as an ESLint ban: the scan also catches the EntityId type name, not only the import, and it needs no new config block for non-sim code whose rule keys a later block would silently replace (RESEARCH Pattern 8). The guard lands in wave 1, so it is in force before ids.ts exists (plan 08-05) and before app code first meets the world (plan 08-15); plan 08-05's Key Decisions row (d) cites it, and plan 08-15 keeps its narrower gate on world-lifecycle.ts. Task 3 writes no file under src/sim, so it needs neither the probe lock nor a change to eslint.config.js.
</objective>
