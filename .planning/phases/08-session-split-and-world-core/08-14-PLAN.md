<objective>
Read the test flags once at start-up and give the sim driver a manual clock and an exact tick-stepping entry point (FOUND-14; D-09, D-10), with no probe change.

Purpose: SwiftShader runs the simulation far slower than wall time, so browser specs need to count ticks instead of seconds. This plan is the driver half: the flags parser, the manual-clock frame branch and advanceTicks with its refusal and taint rules, all proven in Node. Plan 08-15 then plugs the world in (and takes the traffic flag from here), and plan 08-16 exposes advanceTicks and worldHash on the hook in the one deliberate probe commit (D-13) and proves browser/Vitest parity. The former single tick-hook plan was split this way so no plan exceeds ten files while the probe additions remain one commit; this plan and 08-15 list exactly ten (the warning threshold), recorded in their scope notes, and 08-16 lists ten only because its conditional A7 fallback fixture is declared.

Scope note (ten files, at the 10-file warning threshold): the manual clock is one seam that crosses the session modules owning its parts, each touched once: the new parser (test-flags.ts), the runtime field (context.ts), the read-once point (start-session.ts), the stepping entry and shared drain (sim-driver.ts), the manual frame branch (frame-loop.ts), the taint callback (probe-publisher.ts) and the late-bound deps in the facade (game-session.ts), plus three test files. Task 2 is TDD over the same three source files, so splitting would separate the tests from the code they pin and renumber plans 08-15 and 08-16; the plan keeps ten files.

Output: src/app/session/test-flags.ts, the manual-clock branch, advanceTicks and the shared drain path, markHookMutation exposed by the probe publisher, and their unit tests.
