The rule: `nextId` restarts at 101 for every new world (each launch, each arrival, and each in-flight Continue or Load), within one world an id is never reused, and no reference to an entity id may outlive the world that issued it; nothing outside the world (saves, HUD, logs, mission state, targeting across a jump) stores an id. Rationale: a world stays a pure function of its seed (D-02), so the hash, snapshots and browser/Vitest parity stay reproducible. Oolite contrast: `OOUniversalID` is a uint16 in 100..2149 allocated from a wrapping counter that reuses freed slots even within one system and is reset only in `setUpSettings` (/home/opencode/git/oolite/src/Core/OOTypes.h:165-171, Universe.m:5016-5020, Universe.m:9252); Wegolite is deliberately stricter within a world. The next entity id that SAVE-08 has saves carry is the issuing world's own counter, used to regenerate that same world at the leg anchor, and names no entity, so it is consistent with the rule. Implemented by Task 1 (createWorld starts every store at FIRST_DYNAMIC_ID), proven by Task 2's per-world behaviour, recorded as Key Decisions row (d), and relied on by plan 08-15 wherever a world is recreated.
