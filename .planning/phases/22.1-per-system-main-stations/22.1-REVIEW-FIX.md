## Fixed Issues

### WR-01: F2 Load swallows the station-hull load error, tells the player the save is bad, and cannot recover

**Files modified:** `src/app/session/save-controller.ts`, `tests/app/session/save-controller.test.ts`, `CHANGELOG.md`
**Commit:** 1ef847ad
**Applied fix:** The catch in the traffic-on Load now logs the cause with `console.error` (naming the saved station kind), as the hyperspace prefetch does, and the failure copy is "Station data could not be loaded — reload the page" instead of "Save could not be loaded", because the memoised rejection only clears on a reload. The existing rejected-artifact test now asserts the new notice and that the original error is logged, and it fails against the old source (checked by reverting the source). `afterEach` in that test file now calls `vi.restoreAllMocks()` so the console spy does not leak. A line was added under `[Unreleased]` / `Fixed` in `CHANGELOG.md`, as the copy is user-visible.

### WR-02: `loadStationHulls("coriolis")` skips the station-hull assertion its contract promises

**Files modified:** `src/content/ships-static-hulls.ts`, `tests/content/ships-static-hulls.test.ts`, `tests/content/ships-static-hulls-missing-coriolis.test.ts` (new)
**Commit:** d178f481
**Applied fix:** `loadStationHulls` now sends every kind through one memoised path: the Coriolis reads through `loadStaticHulls()` (so the shared file is still read once) and then `assertStationHull`; the other kinds read their own file as before. The reviewer's snippet returned a fresh un-memoised promise on every call, so the result is cached in `cachedStations` instead, and the doc comment was updated. The old test "resolves the Coriolis to the very promise the shared loader returns" asserted promise identity, which no longer holds by design; it now asserts that both loaders resolve to the same artifact object (`resolves the Coriolis to the shared artifact, read once`). The new test file mocks the shared `?raw` artifact with a copy that dropped `coriolis-station` and expects a `StaticHullsError` naming the key; it fails against the old source. The retry tripwire (`tests/guards/static-hull-retry-tripwire.test.ts`) still classifies the module as keeping a rejection, as the known todo records.

### WR-03: Station layer settings key on a Mesh named after the node; the single-primitive-per-node invariant is not asserted

**Files modified:** `src/render/bodies/station.ts`, `tests/render/station.test.ts`
**Commit:** 498cf080
**Applied fix:** Added `requireMeshNode`, which resolves a record node and throws "the `<kind>` station node `<name>` is not a single mesh; its render layer cannot be applied" when the node is not a Mesh. `assembleModel` resolves every record node through it, and the render order, `polygonOffset` and dock `depthTest` settings are now keyed by the resolved Mesh objects (a `Map<THREE.Mesh, ...>`) instead of by `object.name`. Tests: 10 new cases (one per record node of the three kinds) build a Group of two Meshes in place of a node and expect the new error; they fail against the old source. A new guard (`describe.each(STATION_KINDS)("the committed %s GLB")`) reads the three committed GLBs and asserts that every record node is a glTF node holding a mesh with exactly one primitive, which pins the invariant at the content level (`readGlbJson` takes an optional file name, default unchanged). No CHANGELOG line: no user-visible change today.
