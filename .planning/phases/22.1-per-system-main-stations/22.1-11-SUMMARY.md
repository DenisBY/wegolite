# Phase 22.1 Plan 11: Per-kind station models in the render Summary

**Every system now draws its own station: the asset cache loads each kind's GLB lazily and the station body builds from the record's node layers, builds meshless and attaches the model late when it is still loading, and nothing but a countdown toward such a system, a boot or Continue there, or an arrival without a cached model ever fetches a station other than the Coriolis.**

## Accomplishments

- **Cache API.** `AssetCache.loadStation(kind): Promise<GLTF>` (memoised per kind, the record's path checked against `NPC_GLB_PATH_PATTERN` before any fetch, a failed load forgotten, a load settling after `dispose()` not cached) and `station(kind): GLTF | undefined`. `loadCoriolis`, `coriolis()` and the Coriolis path constant are gone. `preload()` = Cobra, buoy and `DEFAULT_STATION_KIND`; `loaded()` is exactly that set; `dispose()` frees every loaded station once.
- **Load and prefetch points (and why there is no all-kinds prefetch).** A station model is requested in exactly three places: (1) `preload()` for the default kind; (2) `start-session.ts`, which awaits the starting system's kind before its first scene (a no-op for Lave, because the memoised preload promise is reused; a Continue at Zaonce or Biarge awaits that kind, on the boot failure surface if it fails); (3) `prefetchStationFor` at the hyperspace countdown start, for the destination only, and the scene itself when it is built for a kind whose model is not cached (an arrival that beats its prefetch, an F2 Load into another kind). There is no fetch of every kind after the first in-flight frame: it would land inside the first-load byte measurement of `budget.spec.ts` and `traffic.spec.ts` (headroom about 504 KB with traffic on and 623 KB off, smaller than the two GLBs) and would hold three decoded texture sets for the session (review HIGH, consensus concern 1). `render-driver.ts`, `budget.spec.ts` and `traffic.spec.ts` are byte-identical to PLAN_BASE (`git diff bad8a1d2 HEAD` over them is empty).
- **Per-kind render layers.** `createStation` reads `stationRecord(kind).nodes` and applies the layers, not the names: the `body` node gets `polygonOffset` 1/1 and `renderOrder` 0, `detail` nodes 1, 2, ... in record order, the `dock` node the next one with `depthTest: true`, every opaque node `depthWrite: true`. Result: Coriolis hull 0 (offset), faceplate 1, tris 2, dock 3 (exactly as before); Dodecahedron hull 0 (offset), faceplate 1, dock 2; Icosahedron mainhull 0 (offset), hull 1 (no offset), dock 2. The missing-node error names the kind and the node. `StationBody.modelKind` is the attached GLB's kind, undefined while meshless.
- **Late attach.** `createStation(layout)` without a GLTF builds the pose and roll with an empty `THREE.Object3D` named `dock` at local (0, 0, -`layout.dockOffset`); `attachModel(gltf)` adds the model exactly once (a second call and a call after `dispose()` do nothing: nothing is cloned, no material is allocated, the GLTF stays only in the cache) and swaps in the model's own dock node. `createSystemScene` starts `assets.loadStation(kind)` itself when `assets.station(kind)` was undefined at build time, attaches on resolve through `SystemScene.attachStationModel`, and logs a rejection (or a GLB missing a record node) once without throwing.
- **Meshless window.** The window lasts as long as the model load. Plan 22.1-10 measured the whole Icosahedron or Dodecahedron set (about 6.5 MB) at 0.12 s sequentially from the remote test machine to this host over the LAN; at 50 Mbit/s the same bytes take about 1 s and at 10 Mbit/s about 5 s. Browser-side WebP decode and GPU upload were not measured here (no browser-timing harness exists for an arrival without a prefetch; plan 22.1-12's browser spec owns the browser side). With the countdown prefetch the window is normally zero: the countdown runs 15 s before the arrival.
- **Flashers (owner decision D-C, 2026-11-27).** The todo `2026-11-27-station-flashers` records that Oolite draws 14 `flasher` subentities per station template (counted in `shipdata.plist`: 14 each in the three templates); `tests/render/station.test.ts` asserts no flasher is drawn for any kind, naming the todo; FIDELITY.md gained the row "Main station flashers (14 `flasher` subentities on each station type) are not drawn (owner decision D-C)" (`src/render/bodies/station.ts:208`, `ShipEntity.m:842-858`, excerpt E-214) whose Fidelity cell starts `divergence: not drawn (deferred, owner decision D-C)` and quotes the D-C flashers sentence plan 22.1-01 wrote into PROJECT.md. PROJECT.md is not edited.
- **Guard.** `PENDING_PRESENTATION` keeps only `src/ui/station-model.ts` (plan 22.1-12); a new case scans every `src/render` file and finds no station constant.
