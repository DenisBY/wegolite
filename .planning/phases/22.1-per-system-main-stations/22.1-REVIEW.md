# Phase 22.1: Code Review Report

**Reviewed:** 2026-11-27
**Depth:** standard
**Files Reviewed:** 118 in scope; production code under `src/`, `tools/` and `scripts/` read in full or by diff, and about 12 of the test files read in detail (listed above). The rest of the test files were screened by diff and pattern scan only (`.only`, `.skip`, `as any`, `@ts-ignore`, tautological `expect`).

## Summary

The per-system station install is sound. Every code path that installs a system (the boot, an F2 Load and a hyperspace arrival) resolves its station through the single `stationFor` call. `enterSystemById` keeps everything that can throw before the commit block, and the commit block only assigns. The layout asserts that the spec kind matches `system.station`. The blockage mass is read from the live layout, which is the origin's, and not from the destination. The hull merge builds a new `Map` and applies it synchronously, so concurrent loads of two kinds cannot lose an update. I checked these Oolite claims against `/home/opencode/git/oolite` and they hold:

- `Universe.m:1550` defaults the `station` key to `coriolis`.
- `OOMesh.m:1385` renames a material only when its `TEXTURES` key is the decimal text of the `NAMES` line index, so `renamedMaterial` in `dat.ts` is faithful.
- The Dodecahedron and Icosahedron templates author `frangible = 0`.
- All three stations' subentities sit at the origin, so the build's use of mesh-local bounds for the hull and contact boxes is correct.

I found no BLOCKER (security, data loss or incorrect simulation behaviour). The weaknesses are three robustness gaps:

- a Load failure that is swallowed and mislabelled,
- a hull loader that does not enforce its own contract for one kind,
- a render layer assignment that depends on an unasserted asset shape.

There are also several stale comments and small duplications. The known and already recorded items are not re-raised:

- The static hull loaders memoise a rejected load (todo `2026-11-27-static-hull-load-retry` and its tripwire).
- The lint todo for `as` casts and source-text tests.

WR-01 below is a consequence of the first item, not a restatement of it.

## Warnings

### WR-01: F2 Load swallows the station-hull load error, tells the player the save is bad, and cannot recover

**File:** `src/app/session/save-controller.ts:454-473`
**Issue:** `await ensureStationHulls(ctx, savedSystem.station)` sits in a `try { } catch { hullsLoaded = false; }` that discards the error. The failure path then calls `failLoad("Save could not be loaded")`. Three consequences:

- Nothing is logged. A dropped chunk fetch, a schema failure from `StaticHullArtifactSchema` and the `mergeStationHulls` "already in the hull table with different data" error all disappear. The hyperspace path logs the same failures in `prefetchStationFor`, and this path should too.
- The copy blames the save, which is intact. The player is steered towards the wrong fix.
- This failure is permanent for the page lifetime. Because of the known memoised rejection in `loadStationHulls`, every later F2 Load of any Dodecahedron or Icosahedron save re-uses the same rejected promise. The Lave-origin arrival path degrades gracefully (the station is merely not a laser candidate), but the Load path hard-fails with no hint that a reload is the only remedy.

**Fix:** Log the error and give a distinct copy that says what to do. The copy is short enough for the F2 notice.
```ts
try {
  await ensureStationHulls(ctx, savedSystem.station);
} catch (error) {
  console.error(
    `Wegolite: the ${savedSystem.station} station hull data could not be loaded for the Load`,
    error,
  );
  hullsLoaded = false;
}
// ...
if (!hullsLoaded) {
  failLoad("Station data could not be loaded — reload the page");
  return;
}
```
Update `tests/app/session/save-controller.test.ts` to match the new copy.

### WR-02: `loadStationHulls("coriolis")` skips the station-hull assertion its contract promises

**File:** `src/content/ships-static-hulls.ts:124-137` (the shortcut is at line 128)
**Issue:** The doc comment says "An artifact that does not hold the kind's ship key is rejected: a station without its hull would be silently immune to lasers." That holds for the Dodecahedron and Icosahedron, whose load goes through `.then(assertStationHull)`. For the Coriolis the function returns `loadStaticHulls()` directly, so a shared artifact without `coriolis-station` (for example a regenerated file that dropped the key from `STATIC_HULL_KEYS`) passes, and the Coriolis becomes silently immune to lasers. Today nothing calls `loadStationHulls("coriolis")` in production, because `ensureStationHulls` returns early when the key is already in the table. The function is exported and tested as a uniform per-kind API, so the asymmetry is a latent trap.

**Fix:** Make the shortcut share the assertion path, with the memoised promise unchanged:
```ts
if (record.hullsFile === SHARED_HULLS_FILE) {
  return loadStaticHulls().then((artifact) => assertStationHull(artifact, kind));
}
```
Alternatively, narrow the doc to the own-file kinds. Add a test that feeds a shared artifact without the key.

### WR-03: Station layer settings key on a Mesh named after the node; the single-primitive-per-node invariant is not asserted

**File:** `src/render/bodies/station.ts:189-248` (`requireNode`, `assembleModel`)
**Issue:** `assembleModel` verifies only that `getObjectByName(node.name)` finds an object. It then applies `renderOrder`, `polygonOffset` and the dock's `depthTest` inside `model.traverse`, looking each Mesh up with `orders.get(object.name)` and `layers.get(object.name)`. This works only because the content build emits exactly one primitive per station node. GLTFLoader then names the Mesh after the node. For a multi-primitive mesh GLTFLoader returns a Group named after the node, with child Meshes named after the glTF mesh (`oolite_ico`, ...). The lookups then miss and the layer settings are silently skipped. The result is z-fighting between the body and its detail layers, with no error. The render test builds synthetic one-Mesh-per-node graphs (`tests/render/station.test.ts` `syntheticCoriolis`), so it cannot see this. The record's own wording, "never inferred from a name", is exactly what the code does at the traverse step. Nothing today breaks: the three committed GLBs have `primitives.length === 1` per mesh (checked in `public/models/*.glb`).

**Fix:** Assert the invariant where the nodes are resolved, so a content change fails loudly:
```ts
function requireMeshNode(model: THREE.Object3D, kind: StationKind, name: string) {
  const node = requireNode(model, kind, name);
  if (!isMesh(node)) {
    throw new Error(
      `Wegolite: the ${kind} station node "${name}" is not a single mesh; its render layer cannot be applied.`,
    );
  }
  return node;
}
```
Use it for every record node, and set the layer settings on the resolved nodes (a `Map<Object3D, layer>`) instead of by `object.name`.

### IN-03: `readArtifact` leaves a malformed file as a raw `SyntaxError`

**File:** `src/content/ships-static-hulls.ts:72-74`
**Issue:** `JSON.parse(await load())` is outside any try/catch, so a corrupt chunk surfaces as a bare `SyntaxError` with no path. The sibling dock-port loader (`src/content/dock-port.ts:65-72`) wraps the same operation in a named `DockPortError`. Phase 22.1 makes this function load three files, and the boot failure surface shows `error.message`, so a bad file now gives the player an unhelpful message.
**Fix:** Wrap the parse and throw `StaticHullsError(\`Wegolite: ${path} is not valid JSON.\`)`, as the dock-port loader does.

### IN-04: The dock-port loader also memoises a rejection, outside the recorded todo and tripwire

**File:** `src/content/dock-port.ts:89-99`
**Issue:** `loadStationDockPort` stores the promise in `cachedByKind` before it settles and never evicts on failure, the same pattern as the known static-hull case. The only caller is the boot's `loadStationRecords`, and a rejected boot is final (the failure surface asks for a reload), so there is no user impact today. The todo and `static-hull-retry-tripwire.test.ts` name only `ships-static-hulls.ts`, so a future reader fixing the hull loaders will not know the dock-port loader has the same shape.
**Fix:** Mention `src/content/dock-port.ts` in the todo `2026-11-27-static-hull-load-retry.md`, or evict on rejection (`.catch((e) => { cachedByKind.delete(kind); throw e; })`) as the asset cache does.

### IN-05: Station constants duplicated outside the record in the content tool

**File:** `tools/oolite-ingest/convert/static-hulls.ts:61,76-81,87-93`; `src/content/ships-static-hulls.ts:45`
**Issue:** `"coriolis-station"` is typed in `STATIC_HULL_KEYS` and `STATIC_NAME_KEYS`, and the literal `"ships-static-hulls.json"` is declared in three places (`SHARED_HULLS_FILE` in the loader, `SHARED_HULLS_FILE` in the tool, `STATIC_HULLS_PATH`) besides `STATION_RECORDS.coriolis.hullsFile`. The station-constants guard scans `src` only, and its header acknowledges the tool exceptions, so this is a recorded choice, but a rename of `STATION_RECORDS.coriolis.shipKey` or `hullsFile` would need three synchronised edits that nothing checks.
**Fix:** Derive the Coriolis entries from the record (`STATION_RECORDS.coriolis.shipKey`, `hullsFile`) in the tool, or add a one-line equality assertion to `tests/content/ships-static-hulls.test.ts`.

### IN-06: Inconsistent failure policy for a station model that cannot be assembled

**File:** `src/render/system-scene.ts:418-421,473-490`; `src/render/bodies/station.ts:254-281`
**Issue:** When the model is already cached, `createStation(layout, gltf)` assembles it inside the scene build. A GLB that lacks a record node throws. Inside an arrival, that is caught in `enterSystemById`, which shows "Hyperspace arrival failed" and freezes the session after the sim has already committed the jump. When the model is still loading, the same defect is logged by the late attach and the session continues with an undrawn station (the recorded T-22.1-25 behaviour). The first case is the stricter one, and a content defect in a loaded GLB is indistinguishable from the second at the player level. Both are defensible, but the difference is undocumented.
**Fix:** Either document the asymmetry in `createSystemScene`'s comment, or build the cached case through the same late-attach guard so a bad asset degrades the same way in both paths.
