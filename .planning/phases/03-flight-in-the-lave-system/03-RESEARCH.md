## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Planet and sky visuals

- **D-01:** Lave's planet surface is generated by a procedural GLSL material using the compiled planetinfo values already available in `src/content/generated/systems/g0.json` — `land_color`, `sea_color`, polar colours, `land_fraction`, `cloud_fraction`, `cloud_alpha`, `air_color`, `air_density`, `ambient_level` and a noise field seeded from `random_seed`. No baked planet texture and no new asset-pipeline step.
- **D-02:** A single planet material handles surface colour, clouds, a thin air-colour rim, and the day/night terminator. Do not add separate cloud or atmosphere shells in Phase 3; this keeps one draw call and avoids transparent-depth interactions with the station.
- **D-03:** The sun is an emissive sphere with an additive corona billboard driven by `corona_flare`, `corona_hues` and `corona_shimmer`. The starfield is deterministic, sized from `sky_n_stars`, seeded by `random_seed`, and tinted by `sun_color`. No baked skybox per system.
- **D-04:** The scene includes a witchpoint beacon at the arrival point, a nav buoy in front of the Coriolis dock, and camera-relative dust particles for speed cues. These are in addition to the planet, sun and Coriolis. Dust is the primary visual feedback that torus drive is engaged.

#### HUD and scanner

- **D-05:** The flight HUD is drawn on a transparent Canvas2D overlay above the WebGL canvas. Use it for vector lines, the scanner ellipse and monospace text; no DOM/SVG HUD and no in-scene WebGL HUD geometry.
- **D-06:** The HUD follows Oolite's classic green-vector layout and information hierarchy: centre crosshair, elliptical scanner with vertical tails at the bottom, compass, aegis indicator, speed/roll/pitch and fuel bars, clock, condition light, and message line. This is the v1 subset from FLGT-05; do not add shields, energy, temperature, missiles, target reticle or MFDs.
- **D-07:** The scanner is a 3D elliptical display with vertical tails and a 25.6 km range. In the traffic-free v1 it plots only the Coriolis station, nav buoy and witchpoint beacon when they are in range. Planets and suns are deliberately excluded, matching Oolite's scanner behaviour and avoiding a dominant planet blob.
- **D-08:** Lay the HUD out once in a fixed 1920×1080 design space, then uniformly scale to fit the window with letterboxed margins. Do not reflow or edge-anchor for ultrawide; preserve classic proportions. Render at device pixel ratio, capped as the existing renderer does.

#### Launch experience

- **D-09:** A new game boots through a minimal title/start screen, then starts docked at Lave's Coriolis. The docked view is a single minimal status panel showing system name, credits (100.0 Cr), ship (Cobra Mk III), fuel (7.0 LY), and a Launch action. No trade, outfitting, market or mission screens in this phase.
- **D-10:** Launch plays a short scripted exit of about 2 seconds: break-pattern/tunnel effect, the Cobra sliding out of the slot with the station's roll (`launchRoll = -station roll`), then control handover. The sequence is skippable on any key after the first viewing. Advance the clock by +10 minutes exactly once at launch.
- **D-11:** Teach first use through the HUD message line only: a launch hint while docked, then torus and speed hints once in flight. Each hint is dismissed after its first successful use. No modal tutorial and no permanent controls overlay.

#### Controls and settings

- **D-12:** Every action implemented in Phase 3 is rebindable through a semantic action map: pitch forward/back, roll left/right, speed increase/decrease, torus, pause, launch, target station, compass cycle, and any other action added by the phase. Include conflict detection and reset-to-defaults.
- **D-13:** Control bindings and preferences persist as one versioned JSON blob in `localStorage`. Do not put settings in IndexedDB; IndexedDB is reserved for game saves in later phases.
- **D-14:** The pause overlay is the single home for Resume, Controls (rebinding) and Settings. It freezes the simulation, is reachable both docked and in flight, and is opened with `p` or `Esc`.
- **D-15:** On window blur and on `visibilitychange` to hidden, auto-pause the simulation and clear all held input. This prevents stuck keys and clock drift, matching Oolite's focus-loss behaviour.

## Summary

Phase 3 is a **composition phase**, not a stack change. Every number the scene and flight model need already exists in `src/content/generated/`; every rendering primitive already exists in Three.js r187; and the deterministic loop, camera-relative contract, sim-purity guard, and container verify chain are already green. The work is to turn those pieces into a playable, faithful Lave: a pure flight module, a system-scene builder with a *moving* camera-relative transform, a Canvas2D HUD, a semantic input/settings layer, and a scene lifecycle that can be torn down without leaks.

Three findings are load-bearing. First, Oolite's `station_roll = "0.08"` is **right-angles per second**, not radians per second; the Coriolis rate is `0.08 × π/2 = 0.1256637 rad/s` (50.0 s per revolution), not 0.08 rad/s (78.5 s). Second, `station_vector` and `sun_vector` are **not unit vectors** in the pinned data; Oolite multiplies them as authored, so the station–planet distance is 82,273.48 m and the sun–planet distance is 906,043.69 m, not 82,320 and 905,520. Third, the GLB converter negated Z, so the Coriolis dock node is at local `z = −500.2561` and the station's model-forward is local **−Z**; any orientation code that assumes `Object3D.lookAt()` points the model's nose/dock at the target will put the dock on the wrong side of the station.

**Primary recommendation:** build the pure sim first (`SystemLayout`, flight config/state/step, torus/mass-lock, launch, hash), prove it with the exact Lave numbers and a flight golden, then build the scene and HUD against that read-only state. Keep the Phase 1 kinematic probe and its golden untouched; add a separate `src/sim/flight/` module rather than mutating the probe. Use a `ShaderMaterial` for the planet with explicit log-depth and colour-space chunks, a CanvasTexture corona whose size follows `R × (1 + 8 × corona_flare)`, and a `?test=1` Playwright hook for scene-swap and fallback proofs. No new npm packages are needed.

### Pattern 1: Camera-relative rendering with a *moving* camera

**What:** the simulation stores float64 world positions. Each rendered frame, compute the interpolated ship pose, derive the camera world pose from it, then subtract that camera world position from every body **in float64** before writing the small result into `Object3D.position`. The camera object stays at the origin and carries only orientation.

**Why it is non-negotiable:** at 1.4e6 m a float32 coordinate has a 0.125 m ULP; the Cobra is 130 m long and the Coriolis dock slot is ~192 m wide. Uploading absolute coordinates would visibly shimmer at exactly the moment the player lines up the slot.

The existing transform is already the right one:

```ts
// src/render/camera-relative.ts:28-34 (verbatim)
export function cameraRelative(world: Point3, camera: Point3): Point3Delta {
  return {
    x: world.x - camera.x,
    y: world.y - camera.y,
    z: world.z - camera.z,
  };
}
```

Phase 1 called it with a fixed `CAMERA_WORLD`; Phase 3 must pass the **interpolated camera world position**:

```ts
// src/main.ts:45-52 (verbatim)
export const CAMERA_WORLD: CameraWorld = { x: 0, y: 0, z: 0 };

/** Only the camera-relative subtraction is allowed to touch Object3D.position. */
function place(obj: THREE.Object3D, world: Point3): void {
  const relative = cameraRelative(world, CAMERA_WORLD);
  obj.position.set(relative.x, relative.y, relative.z);
}
```

Recommended extension (keep `cameraRelative` pure; do not add a second conversion path):

```ts
function placeRelative(obj: THREE.Object3D, world: Point3, camera: Point3): void {
  const rel = cameraRelative(world, camera);
  obj.position.set(rel.x, rel.y, rel.z);
}
```

Rules:
- The camera's `position` is always `(0,0,0)`; only its `quaternion` changes.
- The camera world pose is derived from the **same interpolated ship pose** used for the player hull. Mixing current ship for the camera and interpolated ship for the hull produces sub-metre shimmer at speed.
- The starfield is camera-locked (`position = 0`, identity orientation); dust is camera-local and wrapped; no body may accumulate an absolute position through a parent transform.
- Never write camera-relative values back into sim state.

### Pattern 2: Fixed 1/120 s step, controller intent, rendered interpolation

**What:** one immutable `InputFrame` per RAF; a controller converts it to a `ControlIntent`; commands are drained once; the accumulator runs whole `DT = 1/120` steps (max 5, delta clamp 0.25 s); the renderer interpolates between the previous and current pose.

**Why:** flight ramps, torus mass-lock and launch timing must be frame-rate independent; a recorded input replay must hash identically at 30/60/144 Hz. This is the existing Phase 1 contract, extended to the real flight model.

The controller seam is the FLGT-08 deliverable:

```ts
export interface ControlIntent {
  pitch: number;          // -1..1, + = nose up
  roll: number;           // -1..1, + = roll right (sign verified by probe)
  speed: number;          // -1..0..+1, accelerate/decelerate
  precision: boolean;     // Oolite Ctrl modifier: scale turn input by 0.5
  torusToggle: boolean;   // edge, consumed once
}

export interface ShipController {
  /** Pure: derives an intent from the current read-only view + device frame. */
  update(view: Readonly<FlightView>, frame: Readonly<InputFrame>): ControlIntent;
}
```

`PlayerController` is one implementation; `ScriptedLaunchController` returns zeros; future `AIController` / `DockingController` write the same intent. `stepFlight` must not contain `if (isPlayer)`, `window`, `document`, `three`, `Math.random`, `Date`, or `performance`.

### Pattern 3: Scene lifecycle with an explicit asset cache

**What:** `AssetCache` owns the shared Cobra/Coriolis GLBs and their textures (loaded once). `SystemScene` owns only the resources it creates (planet geometry/material, sun, corona CanvasTexture, starfield, dust, beacon geometry/materials). `MenuScene` owns its own starfield and a Cobra clone. `SceneManager` swaps and disposes.

**Disposal contract:**
- `SystemScene.dispose()` disposes every geometry/material/texture it created and removes its root from the scene. It **must not** dispose cached GLB geometries/materials/textures.
- `AssetCache.dispose()` disposes the shared GLBs and textures once, on app teardown.
- Remove event listeners with an `AbortController` (`addEventListener(..., { signal })`; `controller.abort()`), cancel RAF, clear the HUD canvas.
- Call `renderer.renderLists.dispose()` after a swap if the old scene is gone; assert `renderer.info.memory.geometries/textures` does not grow across repeated swaps.

### Pattern 4: Command/event boundary

**What:** UI and input enqueue tagged `Command` values; the sim applies them at a tick boundary and emits `SimEvent` values; the UI/HUD re-render from state + events. No UI code mutates `FlightState`; no sim code imports `input/`, `render/`, or `ui/`.

Minimum Phase 3 command set:

```ts
export type Command =
  | { kind: "launch" }
  | { kind: "skipLaunch" }
  | { kind: "toggleTorus" }
  | { kind: "setPaused"; paused: boolean }
  | { kind: "cycleCompass" }
  | { kind: "targetStation" };

export type SimEvent =
  | { kind: "launched" }
  | { kind: "launchComplete" }
  | { kind: "torusEngaged"; factor: number }
  | { kind: "torusDisengaged"; reason: "input" | "massLock" | "toggle" }
  | { kind: "massLockChanged"; locked: boolean }
  | { kind: "compassTargetChanged"; target: "planet" | "station" | "witchpoint" };
```

Messages/hints are app/HUD-owned strings derived from events; the sim stays free of UI copy.

### Pattern 5: HUD model + pure projection

**What:** `buildHudModel(state, layout, settings)` returns a plain read-only view model. `render/hud/projection.ts` contains pure scanner/compass math tested in Node. `render/hud/draw.ts` only draws the model, in 1920×1080 design units, after the canvas transform is set.

This separation is what makes FLGT-05 testable without pixel diffing: projection and formatting are unit-tested; the Playwright spec asserts the canvas exists, has a non-zero backing size, and the probe reports the expected element set.

### Anti-Patterns to Avoid

- **Renderer as source of truth:** never read `mesh.position` back into gameplay; never run collision against scene-graph transforms.
- **Absolute positions in `Object3D`:** every body goes through `cameraRelative`; the camera stays at the origin.
- **Variable-dt flight:** never integrate with raw RAF deltas; use the fixed step and clamp.
- **One `Player` god-object:** keep `src/sim/flight` pure and the controller behind `ShipController`; no `if (isPlayer)` in the step.
- **Using `cobra3-trader` or `cobra3-alternate` for the player:** those are 300/30 and 300/32/35 t. Use `oolite_template_cobra3-player` (350/32/20 t).
- **Using `station_roll` as rad/s:** it is right-angles/s; multiply by π/2.
- **Normalising `station_vector`/`sun_vector` before positioning:** Oolite uses them as authored; normalise only for directions.
- **Separate cloud/atmosphere shells:** locked out by D-02; one material, one draw call.
- **DOM/SVG HUD or in-scene HUD quads:** locked out by D-05.
- **`Math.random`/`Date.now`/`performance.now` inside `src/sim`:** already banned by ESLint; extend the same discipline to the flight module.
- **Pixel-diff evidence:** D-08 forbids it; assert probes, counters and finite numerics instead.

**Layout derivation (`src/sim/world/layout.ts`).**

Define a Wegolite system basis: `+X` right, `+Y` up, `-Z` forward (the same basis as the ship and the existing camera). Convert an Oolite vector `(x,y,z)` by negating Z:

```ts
const toWegolite = (v: readonly [number, number, number]): Vec3 => vec(v[0], v[1], -v[2]);
```

Then, mirroring Oolite's `setUpSpace` exactly:

```ts
const planetRadius = system.radiusKm * 10;                 // Oolite scales by 1/100
const planet = vec(0, 0, -system.planetDistance);          // witchpoint is the origin
const stationVector = toWegolite(system.stationVector);    // NOT normalised for position
const station = sub(planet, scale(stationVector, 2 * planetRadius));
const sunVector = toWegolite(system.sunVector);            // NOT normalised for position
let sunDistance = system.sunDistance;
let sun = sub(planet, scale(sunVector, sunDistance));
// Oolite's safe-distance loop: sunPos must be at least 6 sun radii from the origin.
const safe2 = 36 * system.sunRadius * system.sunRadius;
while (lengthSquared(sun) < safe2) {
  sunDistance *= 2;
  sun = sub(planet, scale(sunVector, sunDistance));
}
const stationToPlanet = normalize(sub(planet, station));
const navBuoy = add(station, scale(stationToPlanet, 10_000)); // StationEntity beaconPosition
const witchpoint = vec(0, 0, 0);                              // getWitchspaceExitPosition
```

Additional derived fields:
- Clamp `sunRadius` to `>= 1000` and `<= sunDistance / 2` as Oolite does (`Universe.m:1466-1468`); Lave's 84,449.095459 is unaffected, but the rule keeps the layout valid for other systems.
- `stationBaseQuat = quatFromUnitVectors(vec(0,0,-1), stationToPlanet)`. The model's **local −Z** is its forward/dock direction after the Phase 2 Z-negation; `Object3D.lookAt()` points local **+Z** at the target and would put the dock on the wrong side.
- `stationRollRadPerSec = station.shipDef.stationRoll * Math.PI / 2`, read from the `coriolis-station` entry (see the fidelity correction in § Data & Constants). If `stationRoll` is absent, throw a named error or use Oolite's `STANDARD_STATION_ROLL 0.4` only as a logged, deliberate fallback; do not silently use 0.
- `dockOffset = abs(dockSubentity.position[2])` from `coriolis-station.shipDef.subentities` (`500.2561`), or a checked fallback.
- `stationRadius = 500` (GLB x/y half-extent; the z extent is 1,034.3 including the dock tunnel). Assert the GLB half-extent in a test.
- `scannerRange = 25_600`, `stationAegisRange = 51_200`, `planetAegisRange = 3 * planetRadius`.
- `sunDir = normalize(sub(sun, planet))` for lighting and the planet shader.

**Math helpers.** Add to `src/sim/math.ts`:
- `sub`, `add`, `scale`, `lengthSquared`, `length`, `normalizeVec` (if not already present in a different form);
- `quatFromUnitVectors(from, to)` with the antiparallel fallback;
- `conjugate(q)` and `rotateInverse(q, v)`;
- `nlerp`/`slerp` for render interpolation (or keep interpolation in `render/`, but the quaternion math should be shared);

All are pure; no Three, no DOM, no `Math.random`. Test the antiparallel case explicitly (`from = -to`), because the standard cross-product formula degenerates there.

**Attitude (`attitude.ts`).**

Oolite's player keyboard path:
- `roll_delta = 2.0 * max_flight_roll` → 4 rad/s² for the Cobra.
- `pitch_delta = 2.0 * max_flight_pitch` → 2 rad/s².
- Max rates clamp at `max_flight_roll = 2` and `max_flight_pitch = 1`.
- When no key is held, the rate moves toward 0 at `1.0 rad/s²` (`ROLL_DAMPING_FACTOR` / `PITCH_DAMPING_FACTOR`).
- When reversing, the keyboard path zeroes the rate (`if (flightRoll > 0) flightRoll = 0`) and ramps from zero at the normal rate. The 4× reversal factor in `applySticks` is the **AI/joystick** path; do not apply it to the v1 keyboard model unless a deliberate feel decision is recorded.

```ts
function slew(rate: number, target: number, accel: number, damp: number, dt: number): number {
  if (target === 0) {
    const step = damp * dt;
    return Math.abs(rate) <= step ? 0 : rate - Math.sign(rate) * step;
  }
  if (rate * target < 0) rate = 0;             // reversal: zero first, as the keyboard path does
  const step = accel * dt;
  return rate < target ? Math.min(rate + step, target) : Math.max(rate - step, target);
}
```

Then compose roll then pitch, matching Oolite's `applyRoll:andClimb:` order:

```ts
const rollQ = axisAngle(0, 0, 1, state.rollRate * dt);
const pitchQ = axisAngle(1, 0, 0, state.pitchRate * dt);
state.orientation = normalize(mul(mul(state.orientation, rollQ), pitchQ));
```

**Sign verification is mandatory.** In the Wegolite basis, `+X` rotation is nose-up for a `-Z` forward; `+Z` rotation is visually a roll *left* when looking along `-Z`. Define `roll = +1` for the right-arrow action, then verify with a unit test: after a short positive roll, the local right vector `(1,0,0)` should have a **negative Y** component (right wing down). If the sign is wrong, negate `rollRate` at the composition point, not in the input map. Do not guess; the test pins it.

**Speed (`speed.ts`).**

Oolite is Aristotelian: one scalar `flightSpeed`; position advances along the ship's forward vector; there is no persistent lateral velocity.

```ts
const forward = rotate(state.orientation, vec(0, 0, -1));
state.position = add(state.position, scale(forward, state.speed * dt));
```

Normal speed changes:
- `speedUp` held: `speed += thrustAccel * dt` (160 u/s²).
- `speedDown` held: `speed -= thrustAccel * dt`.
- Clamp `0..maxSpeed` (350) in normal flight.
- No drift; a turn changes the direction of travel immediately because velocity is derived from the orientation each step.

Torus speed is handled in `torus.ts` (below). When torus disengages above `maxSpeed`, decelerate toward `maxSpeed` at `thrustAccel × lastFactor`, **×3 when the disengage was a mass lock** (Oolite's multiplier); do not instant-clamp. This preserves the “slowing from hyperspeed” feel and matches the source’s input-vs-mass-lock difference.

**Torus and mass lock (`torus.ts`).**

```ts
function nearestSurfaceDistance(pos: Vec3, layout: SystemLayout): number {
  const bodies = [layout.station, layout.navBuoy, layout.witchpoint, layout.planet, layout.sun];
  let best = Infinity;
  for (const body of bodies) {
    best = Math.min(best, Math.max(0, distance(pos, body.position) - body.radius));
  }
  return best;
}

function torusFactor(nearestSurface: number, range = 25_600): number {
  const factor = nearestSurface / (4 * range);
  return clamp(32 * Math.sqrt(Math.max(1, factor)), 32, 1024);
}
```

While engaged:
- `factor = torusFactor(nearestSurfaceDistance(...))` each tick.
- `target = maxSpeed * factor`.
- `speed = moveToward(speed, target, thrustAccel * factor * dt)`.
- If `massLocked` → disengage immediately, emit `torusDisengaged {reason:"massLock"}`, set `lastFactor`, and decelerate.
- If the player gives pitch/roll/speed input (or presses `j`) → disengage; the acceptance text says any pilot input, which is stricter than Oolite's speed-only keyboard disengage. Record this as a deliberate, documented divergence if the planner keeps it.

Mass lock predicate (Oolite `checkEntityForMassLock`, station/planet/sun only in v1):
- **Station:** `distance <= 25_600` from the station centre (Oolite uses `zero_distance <= SCANNER_MAX_RANGE²`).
- **Planet:** `d² < 4r²` (within 2 radii of the centre, i.e. 41,160 m above Lave's surface) **or** within 25 km of the surface (`d² < r² + 50_000r + 625_000_000`).
- **Sun:** `d² < 2r²` (within √2 radii, i.e. ~35 km above Lave's surface) **or** within 25 km of the surface.
- **Buoys:** do not mass lock (Oolite's `CLASS_BUOY` branch is a no-op). They *do* count as nearest bodies for the torus factor.

At the station (500 m), the factor is 32 (mass-locked anyway). At the witchpoint, if the witchpoint buoy is the nearest surface, the factor is 32; once away from the buoy, the nearest is the station/planet and the factor rises. Lave's whole 1.14e6 m extent can only reach ~107×; 1024× is a cap for interstellar-scale emptiness, not a Lave value.

**Launch (`launch.ts`).**

On `launch` (docked only):
```
mode = "launching"; launchElapsed = 0; launchCount += 1;
clockSeconds += 600;                         // exactly once
position = station.position + stationToPlanet * dockOffset; // 500.2561 m out
orientation = stationBaseQuat;               // local -Z -> stationToPlanet
speed = launchSpeed;                         // 175
pitchRate = 0;
rollRate = stationRollRadPerSec;             // sign chosen so the slot is steady (verify)
stationAngle = 0;                            // deterministic launch start
```
Each launching step:
- `speed = moveToward(speed, launchSpeed, thrustAccel * dt)` (hold 175);
- `position += forward * speed * dt`;
- `stationAngle += stationRollRadPerSec * dt`;
- `orientation = normalize(orientation * axisAngle(0,0,1, stationRollRadPerSec * dt))`;
- `launchElapsed += dt`; at `>= 2.0` or skip → `mode = "inFlight"`, `rollRate = 0`, emit `launchComplete`.

The Oolite source sets `ship_clock_adjust += 600` and `launchRoll = -flightRoll` in its own basis. The *magnitude* is settled; the sign after the Z reflection is not. The recommended Wegolite implementation sets the ship's launch roll **equal** to the station's world roll rate so the slot appears stationary during the scripted exit; verify with a probe that measures the station's relative roll over 1 s. If the sign is inverted, the slot will visibly counter-rotate at 2× the station rate. This is an explicit MEDIUM-confidence item in § Assumptions Log.

**Step order inside `stepFlight`:**
1. Drain commands exactly once (first step of a frame only).
2. Apply mode transitions (launch/dock/pause is app-owned).
3. Compute the control intent from the controller (or scripted launch).
4. Update attitude rates and orientation.
5. Update torus/mass lock and speed.
6. Integrate position along forward.
7. Advance station angle, flight time, clock (clock only in launching/inFlight; docked is static).
8. Emit events.

### Step 5 — Bodies and rendering

**Files:** `src/render/bodies/*`, `src/render/shaders/planet.glsl.ts`, `src/render/system-scene.ts`, `src/render/sync.ts`; tests/e2e.

**Planet (`planet.ts` + `planet.glsl.ts`).**
- Geometry: `SphereGeometry(planetRadius, 192, 96)` or `256×128`; one mesh, one `ShaderMaterial`, `side: FrontSide`, `depthWrite:true`. Tessellation only affects the silhouette; the surface detail is per-fragment.
- Vertex shader must include, in order:
  ```glsl
  #include <common>
  #include <logdepthbuf_pars_vertex>
  ...
  #include <logdepthbuf_vertex>
  ```
- Fragment shader must include:
  ```glsl
  #include <common>
  #include <logdepthbuf_pars_fragment>
  ...
  #include <logdepthbuf_fragment>
  #include <tonemapping_fragment>
  #include <colorspace_fragment>
  ```
  Without the log-depth chunks, a custom shader writes conventional depth and the planet/station depth order will be wrong at long range. Without `colorspace_fragment`, the planet will be dark/oversaturated under `outputColorSpace = SRGBColorSpace`.
- Uniforms: `uSeed` (from `random_seed`), `uLandColor`, `uSeaColor`, `uPolarLandColor`, `uPolarSeaColor`, `uPolarCloudColor`, `uCloudColor`, `uAirColor`, `uLandFraction`, `uCloudFraction`, `uCloudAlpha`, `uAirDensity`, `uAmbient`, `uSunDir` (object-space), `uTerminator` (from `terminatorThresholdVector`), `uTime`, `uNoiseScale`, `uOctaves`.
- Surface: 4–6 octave 3D value/simplex noise on `normalize(localPosition)`; `land = smoothstep(threshold - 0.02, threshold + 0.02, n)`, with `threshold` calibrated so the land area approximates `land_fraction = 0.65` (do not hardcode 0.5); mix sea/land; blend polar colours by `smoothstep(0.6, 0.95, abs(local.y))`.
- Clouds: a second noise field, `cloud = smoothstep(1 - cloud_fraction, 1 - cloud_fraction + 0.05, c) * cloud_alpha`; mix `cloud_color` and `polar_cloud_color`. No separate shell (D-02).
- Terminator: `day = smoothstep(-softness, softness, dot(N, uSunDir))`; `light = ambient + (1 - ambient) * day`; ambient = 0.1. Add a thin `air_color` rim via `pow(1 - max(dot(N,V),0), 3) * air_density * day`.
- Planet spin: `planetQuat = axisAngle(0,1,0, rotation_speed * flightTime)`; update `uSunDir` in object space each frame (`rotateInverse(planetQuat, sunDirWorld)`). Optional; if omitted, the planet is static and the terminator still works.
- No world-space position in the noise; all sampling is object-space normalized. This keeps the shader precision-independent at 452 km.

**Sun + corona (`sun.ts`).**
- Sun: `SphereGeometry(sunRadius, 64, 32)` + `MeshBasicMaterial({ color: sunColor, toneMapped:false })`; built-in material handles log depth. `sun_color` is white for Lave; the disc is bright.
- Corona: **do not interpret `corona_hues` as a hue or `corona_shimmer` as intensity.** In Oolite:
  - `corona_flare` sets the outer radius: `corouter = R * (1 + 8 * corona_flare)`; for Lave `0.028528` → `1.2282R` (a thin rim, not a 3–4R halo).
  - `corona_hues` is `corona_blending`, a 0–1 blend between two inner corona layers.
  - `corona_shimmer` is an animation speed (`0.597 * 2 + rand^2 ≈ 1.19+`), not a brightness.
- Implementation recommendation: a camera-facing `PlaneGeometry`/`Sprite` with a **CanvasTexture radial gradient** generated from the sun colour and `corona_blending`, `AdditiveBlending`, `depthWrite:false`, `depthTest:true`, `toneMapped:false`; modulate scale/opacity slowly with `corona_shimmer`. This uses built-in material log depth (no custom shader chunks) and is deterministic. A custom additive shader is acceptable if it includes the log-depth chunks.
- The corona plane must face the camera each frame (`quaternion.copy(camera.quaternion)` and `DoubleSide`, or rotate the plane 180° so its front face points at the camera) and be placed at the sun's camera-relative position. Its radius is ~103,700 m (a plane ~207,000 m across); at 1.14e6 m, float32 is fine (0.125 m ULP).

**Starfield (`starfield.ts`).**
- Count = `system.sky_n_stars` (Lave 8,887), capped at 20,000 for performance. Use a deterministic seed from `random_seed` (parse the six bytes, hash to 32-bit).
- Uniform sphere sampling; shell radius 1.5e6 m (inside the 2.5e6 far plane, outside the sun at 1.14e6). `Points` with `size: 1.5–2`, `sizeAttenuation:false`, `depthWrite:false`, `depthTest:true`, `vertexColors` for subtle variation.
- Tint by `sun_color` (white for Lave); mix ~80% white / 20% tint so a coloured sun does not turn the whole sky monochrome. The starfield object sits at the camera origin, identity orientation; the camera's rotation changes the view, the camera's translation does not move the sky.
- Ignore `sky_n_blurs` in Phase 3 (it is a nebula/blur count, not star count); note it for later.

**Station (`station.ts`).**
- Clone `coriolis.glb` from the cache; node names are `hull`, `faceplate`, `tris`, `dock`; dock local translation is `[0,0,-500.2561]` (already converted). Do not re-add the dock transform.
- Set `stationRoot.quaternion = stationBaseQuat * axisAngle(0,0,1, stationAngle)` (local Z is the roll axis; the model's dock is at local −Z).
- Z-fighting: the four nodes are coplanar/near-coplanar and the dock is only 0.2561 m outside the hull. Set `polygonOffset: true`, `polygonOffsetFactor: 1`, `polygonOffsetUnits: 1` on the **hull** (push it back), and leave faceplate/tris/dock at 0; optionally `renderOrder` hull 0, faceplate 1, tris 2, dock 3. Keep `depthWrite:true` for all opaque nodes. Do not use `depthTest:false` on the dock.
- Materials: the GLB uses `MeshPhysicalMaterial` (KHR_materials_specular) and baked emissive textures with `emissiveFactor [1,1,1]`. Set `emissiveIntensity` to a tuned value (start ~0.6–1.0) so the Coriolis doesn't glow uniformly; test visually. Set the dock material `side: DoubleSide` if the tunnel interior is single-sided.
- Radius: use 500 for mass-lock/layout; the z extent (1,034.3) includes the dock tunnel. Assert the GLB x/y half-extent is 500 ± 0.01 in a test.

**Cobra (`ship.ts`).**
- Clone `cobra3.glb` from the cache; it has one mesh with two primitives (Hull, Gun), two materials, bounds `130 × 34.96 × 81.37` (x/y/z), nose at local −Z.
- Cockpit flight: hide the Cobra mesh (first-person). Launch cinematic: show it. `visible` toggles; do not rebuild.
- Place at `state.position`, `quaternion = state.orientation`. During cockpit flight the camera is at `state.position + rotate(orientation, viewOffset)`, so the ship mesh is hidden to avoid clipping.
- `view_position_forward` is authored `0.0 7.25 31.0` in Oolite +Z; convert to `(0, 7.25, -31)` in the Wegolite basis. The camera is ~12.5 m behind the nose; the near plane 0.5 is safe because the hull is hidden.

**Beacons (`beacon.ts`).**
- Nav buoy at `station + stationToPlanet * 10_000`; witchpoint at `(0,0,0)`. No Oolite buoy GLB is vendored, so use a small procedural marker: an 8–20 m `OctahedronGeometry` with an emissive `MeshBasicMaterial` plus a `Points`/sprite dot (`size: 2–3`, `sizeAttenuation:false`) so it is visible at long range. A slow pulse is optional and render-time only.
- Scanner entries use the same positions and radii (station 500, buoys ~10).

**Lighting.** One `DirectionalLight` whose direction is `normalize(planet - sun)` (from sun toward the scene), plus `AmbientLight` intensity `ambient_level` (0.1). No shadows, no `<br>`/post-processing. Set `renderer.toneMapping = NoToneMapping` (Oolite-like, not ACES). The planet shader gets its own `uSunDir`; the GLB materials use the directional light.

**Tests.**
- `tests/render/planet-shader.test.ts` reads the shader source string and asserts all four log-depth chunk names + `colorspace_fragment` are present.
- `tests/render/starfield.test.ts` asserts the count equals `sky_n_stars`, positions are unit-length × shell radius, and two builds from the same seed are identical.

### Step 6 — HUD (Canvas2D)

**Files:** `src/render/hud/hud.ts`, `projection.ts`, `draw.ts`, `format.ts`, `messages.ts`, `src/app/hud-model.ts`; tests.

**Canvas lifecycle.**
- One `<canvas id="hud">` absolutely positioned over the WebGL canvas, `pointer-events:none`, `aria-hidden="true"`.
- On resize: `dpr = Math.min(window.devicePixelRatio || 1, 2)`; `canvas.width = round(innerWidth*dpr)`, `canvas.height = round(innerHeight*dpr)`, CSS size = innerWidth/innerHeight. Compute `scale = min(canvas.width/1920, canvas.height/1080)`, `offsetX = (canvas.width - 1920*scale)/2`, `offsetY = (canvas.height - 1080*scale)/2`; `ctx.setTransform(scale,0,0,scale,offsetX,offsetY)`. Draw in design units. Guard zero dimensions.
- For the full-screen break pattern, `ctx.save()`, reset to `setTransform(dpr,0,0,dpr,0,0)`, draw in device pixels, `restore()`. Do not let the tunnel effect inherit the letterbox transform.
- Redraw once per rendered frame (or at 30 Hz if profiling shows cost); do not update DOM text per frame.

**Scanner projection (`projection.ts`, pure).**
- `local = rotateInverse(shipOrientation, targetWorld - shipWorld)`; Wegolite ship frame: `x` right, `y` up, `z` backward; `forward = -local.z`.
- `zFactor = scannerHeight / scannerWidth` (Oolite's 64/288 ≈ 0.222; a 360×80 design keeps the same 4.5:1 ratio); `yFactor = 1 - sqrt(zFactor)` (~0.529).
- `scale = 0.5 * scannerWidth / scannerRange`.
- `x = local.x * scale`; `yBase = forward * zFactor * scale` (positive forward plots **down** in canvas coordinates); `tail = -local.y * yFactor * scale` (positive up plots **up**).
- Blip line from `(cx+x, cy+yBase)` to `(cx+x, cy+yBase+tail)`; draw a small diamond at the base for the station, a dot for buoys. Clip the scanner region to a rect so tails cannot cross the message line.
- Visibility: `distance - radius <= range`; if `distance > range` but within `range + radius`, clamp/scale the relative vector to the rim; otherwise omit. Lave at launch: station at ~500 m and nav buoy at ~10 km are visible; the witchpoint at 434 km is not until you fly near it. Planet/sun are deliberately excluded (D-07).
- No scanner zoom in Phase 3; the projection takes a `zoom` constant of 1 for future use (DISCUSSION-LOG defers zoom).

**Compass projection.**
- `local` as above; `horizontal = local.x`, `vertical = local.y`; `mag = hypot(horizontal, vertical)`; screen direction `(horizontal/mag, -vertical/mag)`; blip at `(cx + nx * 0.4r, cy + ny * 0.4r)`; colour green if `forward >= 0`, amber/red if behind. If `mag ≈ 0`, draw at the centre.
- Basic/auto target: station when `aegis === "dockingRange"` or `aegis === "planet"` (Oolite's basic compass switches to the station inside the planetary aegis); otherwise planet. Manual cycle (`\`): planet → station → witchpoint → auto. Show a small label (P/S/W or full name).
- Aegis: station within 51,200 m = `dockingRange`; else planet within `3 * planetRadius` (123,480 m for Lave) = `planet`; else `none`. Draw the aegis indicator only in `dockingRange` (Oolite's `drawAegis` checks `AEGIS_IN_DOCKING_RANGE`).

**Bars/clock/condition.**
- Speed bar: `speed / maxSpeed`; numeric `speed / 1000` with 3 decimals + `" LS"` (1 LS = 1,000 game units/s), matching Oolite's display convention. Do not mix LS and LM.
- Roll/pitch bars: signed current rate / max rate, centre-zero.
- Fuel bar: `fuel / 70`; display `7.0 LY`.
- Clock: `formatClock(clockSeconds)` → `%07d:%02d:%02d:%02d`; day = floor(clock/86400), hours/minutes/seconds from the remainder. Starting clock = `2084004 * 86400`; after launch +600 s.
- Condition light: green only in Phase 3 (FEATURES' v1 subset); do not tie it to mass lock or torus.
- Message line: bottom centre above the scanner; monospace; black stroke/shadow; max ~900 design px; one line with ellipsis. `MessageQueue` shows one at a time, FIFO, cap 4; expiry uses `flightTime` so pause freezes it. Hints are app-owned; the sim emits events, the app maps to strings.

**Tests.**
- `tests/hud/projection.test.ts`: target dead ahead → base at bottom-centre, tail 0; target above → tail goes up; target behind → base above centre; target at rim → x = ±half-width; planet/sun never appear in contacts.
- `tests/hud/format.test.ts`: clock day/hour/minute/second; speed `0.350 LS`; fuel `7.0 LY`; message queue expiry/FIFO.
- `tests/e2e/hud.spec.ts`: HUD canvas has non-zero `width/height`, `__wegolite.hud.elements` contains crosshair/scanner/compass/aegis/speed/roll/pitch/fuel/clock/message/condition, and resizing to an ultrawide window keeps the design scale letterboxed (no element outside the design rect). Manual readability pass.

If the captured code is already bound to another action, reject and show “Already bound to Roll Left”; do not silently unbind. A “Reset to defaults” button restores the table above. `localStorage` writes on every successful change.
- Clear all held keys on `blur`, `visibilitychange` hidden, `pointerlockchange`, `fullscreenchange`, pause, and launch; also on `pagehide`.

### Step 8 — Launch cinematic, dust, break pattern

**Launch camera.** A 2 s cinematic in world space:
- Start from a point in front of the dock, offset to the side/up: `dockPos + stationToPlanet*220 + stationRight*110 + stationUp*60`; look at the ship (`shipPos` or `dockPos + stationToPlanet*80`). The camera is static or slowly dollies; the Cobra rolls out of the slot against the station.

- At handover, cut to the cockpit: `cameraWorld = shipPos + rotate(shipOrientation, viewOffset)`, `cameraQuaternion = shipOrientation`. The break-pattern overlay covers the cut.
- The Cobra is visible during the cinematic; hide it at handover.

**Break pattern.** Canvas2D full-screen overlay:
- 0–0.2 s: white flash + radial streaks; 0.2–1.6 s: tunnel of 32–48 radial lines/rings scaling outward with a dark centre; 1.6–2.0 s: fade out. Deterministic (seeded from `launchCount` or a fixed seed), not `Math.random`.

**Dust.**
- `LineSegments`/`Points` cloud of 600–1,200 motes in a 400–600 m box around the camera. Positions are camera-local (small floats); each frame subtract the camera's world delta from the local positions and wrap each axis modulo the box size. Never store the absolute camera position in the geometry.
- Segment length scales with `speed / maxSpeed` and `torus.factor` (e.g. `length = clamp(speed * 0.02, 0.5, 40)`); at 66× the streaks are long and sparse, which reads as motion. `depthWrite:false`, `depthTest:true`, additive/alpha blending; colour a pale blue/white.
- Re-seed/wrap on large teleports; no per-frame allocation (reuse `Float32Array`s).

**Fidelity correction 1 — the authored vectors are not unit-length.** `stationVector` magnitude is `0.9994348402972553`; `sunVector` magnitude is `1.0005783327656061`. Oolite multiplies the authored vector by the scalar distance without renormalising (`[CITED: Universe.m:1547]`, `[CITED: Universe.m:1480]`). Therefore:
- station–planet = `82,320 × 0.99943484 = 82,273.476` m, **not** 82,320 m;
- sun–planet = `905,520 × 1.000578 = 906,043.692` m, **not** 905,520 m.

Use the raw vectors for **positions**; normalise only for **directions** (station orientation, nav-buoy offset, light direction). A test that normalises before positioning will disagree with Oolite by 47 m at the station and 524 m at the sun — small visually, but a fidelity test should pin the authored behaviour.

**Fidelity correction 2 — `station_roll` is right-angles per second.** `shipdata.plist` authors `station_roll = "0.08"; // 1G at rim` (`[VERIFIED: third_party/oolite/Config/shipdata.plist:1742]`). Oolite's setter multiplies by π/2:


The Elite Wiki confirms: “unlike the other turn rate properties, for historical reasons station_roll is measured in right-angles/second, not radians/second.” `[CITED: https://wiki.alioth.net/index.php/Shipdata.plist#station_roll]`

Therefore the Coriolis angular rate is `0.08 × π/2 = 0.12566370614359174 rad/s`, period **50.0 s**, not 0.08 rad/s / 78.5 s. The CONTEXT shorthand “0.08 rad/s” must be read as the authored value; derive the rad/s rate in code as `stationRoll * Math.PI / 2`. If the project intentionally chooses 0.08 rad/s for feel, record it as a deliberate divergence; the faithful value is 0.1256637 rad/s.

### 1. Lave layout with the authored vectors and sun safe-distance loop

```ts
// src/sim/world/layout.ts — pure, no Three.
import type { System } from "../../content/types.js";
import { add, lengthSquared, normalizeVec, scale, sub, vec, type Vec3 } from "../math.js";

const toWegolite = (v: readonly [number, number, number]): Vec3 => vec(v[0], v[1], -v[2]);

export function deriveSystemLayout(system: System): SystemLayout {
  const planetRadius = system.radiusKm * 10;              // 41,160 for Lave
  const planet = vec(0, 0, -system.planetDistance);        // witchpoint at origin
  const stationVector = toWegolite(system.stationVector);  // do NOT normalize for position
  const station = sub(planet, scale(stationVector, 2 * planetRadius));
  const stationToPlanet = normalizeVec(sub(planet, station));

  const sunVector = toWegolite(system.sunVector);          // do NOT normalize for position
  let sunDistance = system.sunDistance;
  let sun = sub(planet, scale(sunVector, sunDistance));
  const safe2 = 36 * system.sunRadius * system.sunRadius;  // 6 sun radii, squared
  while (lengthSquared(sun) < safe2) {
    sunDistance *= 2;
    sun = sub(planet, scale(sunVector, sunDistance));
  }

  return {
    planet: { position: planet, radius: planetRadius },
    station: { position: station, radius: 500 },
    sun: { position: sun, radius: system.sunRadius },
    navBuoy: { position: add(station, scale(stationToPlanet, 10_000)), radius: 10 },
    witchpoint: { position: vec(0, 0, 0), radius: 10 },
    stationToPlanet,
    stationBaseQuat: quatFromUnitVectors(vec(0, 0, -1), stationToPlanet),
    stationRollRadPerSec: 0.08 * Math.PI / 2,               // 0.1256637 rad/s
    dockOffset: 500.2561,
    scannerRange: 25_600,
    stationAegisRange: 51_200,
    planetAegisRange: 3 * planetRadius,
    sunDir: normalizeVec(sub(sun, planet)),
  };
}
```

### 2. `quatFromUnitVectors` with the antiparallel fallback

```ts
// src/sim/math.ts — pure.
export function quatFromUnitVectors(from: Vec3, to: Vec3): Quat {
  const d = from.x * to.x + from.y * to.y + from.z * to.z;
  if (d < -0.999999) {
    // 180° about any axis perpendicular to `from`.
    const axis = Math.abs(from.x) < 0.9 ? vec(1, 0, 0) : vec(0, 1, 0);
    const c = cross(from, axis);
    return normalize(quat(0, c.x, c.y, c.z));
  }
  const c = cross(from, to);
  return normalize(quat(1 + d, c.x, c.y, c.z));
}
```

Test: `rotate(quatFromUnitVectors(a,b), a)` equals `b` for parallel, antiparallel and arbitrary unit vectors; quaternion length is 1.

```ts
// src/sim/flight/attitude.ts
export function stepAttitude(state: FlightState, control: ControlIntent, cfg: FlightConfig, dt: number): void {
  const pitchTarget = control.pitch * cfg.maxPitch;
  const rollTarget = control.roll * cfg.maxRoll;
  state.pitchRate = slew(state.pitchRate, pitchTarget, cfg.pitchAccel, cfg.damping, dt);
  state.rollRate = slew(state.rollRate, rollTarget, cfg.rollAccel, cfg.damping, dt);

  // Convention: control.roll = +1 is "roll right" (starboard wing down).
  // A +Z rotation moves local +X toward +Y, which is a LEFT roll, so negate here.
  const rollQ = axisAngle(0, 0, 1, -state.rollRate * dt);
  const pitchQ = axisAngle(1, 0, 0, state.pitchRate * dt);
  state.orientation = normalize(mul(mul(state.orientation, rollQ), pitchQ));
}

// src/sim/flight/speed.ts
const FORWARD = vec(0, 0, -1);

export function stepSpeed(state: FlightState, control: ControlIntent, cfg: FlightConfig, dt: number): void {
  if (state.torus.engaged) {
    const target = cfg.maxSpeed * state.torus.factor;
    state.speed = moveToward(state.speed, target, cfg.thrustAccel * state.torus.factor * dt);
  } else if (state.speed > cfg.maxSpeed) {
    const massLockMultiplier = state.torus.massLocked ? 3 : 1;
    state.speed = moveToward(
      state.speed,
      cfg.maxSpeed,
      cfg.thrustAccel * state.torus.lastFactor * massLockMultiplier * dt,
    );
  } else {
    state.speed = clamp(state.speed + control.speed * cfg.thrustAccel * dt, 0, cfg.maxSpeed);
  }
  const forward = rotate(state.orientation, FORWARD);
  state.position = add(state.position, scale(forward, state.speed * dt));
}
```

**Sign probe:** after `control.roll = +1` for 100 ticks, assert `rotate(state.orientation, vec(1,0,0)).y < 0` (right wing down). If not, negate `state.rollRate` at the quaternion composition, not in the input map.

### 4. Torus factor and mass lock

```ts
// src/sim/flight/torus.ts
export function massLocked(pos: Vec3, layout: SystemLayout): boolean {
  const stationD2 = distanceSquared(pos, layout.station.position);
  if (stationD2 <= 25_600 * 25_600) return true;

  const planetD2 = distanceSquared(pos, layout.planet.position);
  const pr = layout.planet.radius;
  if (planetD2 < 4 * pr * pr) return true;
  if (planetD2 < pr * pr + 50_000 * pr + 625_000_000) return true;

  const sunD2 = distanceSquared(pos, layout.sun.position);
  const sr = layout.sun.radius;
  if (sunD2 < 2 * sr * sr) return true;
  if (sunD2 < sr * sr + 50_000 * sr + 625_000_000) return true;

  return false;
}

export function torusFactor(nearestSurface: number): number {
  return clamp(32 * Math.sqrt(Math.max(1, nearestSurface / (4 * 25_600))), 32, 1024);
}
```

### 5. Scanner projection (pure, canvas coordinates)

```ts
// src/render/hud/projection.ts
export interface ScannerBlip {
  x: number;
  yBase: number;
  yTail: number;
  visible: boolean;
}

export function projectToScanner(
  relativeWorld: Vec3,
  shipOrientation: Quat,
  width: number,
  height: number,
  range = 25_600,
): ScannerBlip {
  const local = rotateInverse(shipOrientation, relativeWorld); // x right, y up, z back
  const forward = -local.z;
  const distance = Math.hypot(local.x, local.y, local.z);
  const zFactor = height / width;
  const yFactor = 1 - Math.sqrt(zFactor);
  const scale = (0.5 * width) / range;

  const x = local.x * scale;
  const yBase = forward * zFactor * scale;      // +forward plots down
  const yTail = -local.y * yFactor * scale;     // +up plots up
  return { x, yBase, yTail, visible: distance <= range };
}
```

```ts
export const SETTINGS_VERSION = 1 as const;

export interface SettingsV1 {

  bindings: Partial<Record<ActionId, string[]>>;

  launchSeen: boolean;
```

## Common Pitfalls

### Pitfall 1 — Absolute positions or a camera that stays at the origin

**What goes wrong:** the station/planet shimmer as the ship moves; the dock slot “swims” during approach; distant bodies snap in a grid.
**Why:** float32 upload of coordinates at 4.5e5–1.4e6 m has 3 cm–12.5 cm ULP; the Cobra is 130 m and the slot is ~192 m.
**How to avoid:** every body goes through `cameraRelative(world, cameraWorld)`; the camera object stays at `(0,0,0)` and only rotates; no absolute position in a parent transform; no world-space shader uniform.
**Warning signs:** the problem disappears when the station is moved to `(0,0,0)`; `mesh.position` contains values >1e5; a custom shader uses `modelMatrix` translation for noise.

### Pitfall 2 — Z-fighting on the four Coriolis layers

**What goes wrong:** the faceplate/tris/dock flicker or zipper against the hull, especially at 10–100 km; the dock opening looks like a moiré.
**Why:** the dock is only 0.2561 m outside the hull; the four nodes are coplanar/near-coplanar; log depth helps but does not eliminate coincident surfaces.
**How to avoid:** `polygonOffset` on the hull (push back) with factor/units +1; keep faceplate/tris/dock at 0; explicit `renderOrder` hull→faceplate→tris→dock; `depthWrite:true` for opaque nodes; do not disable depth test on the dock. Test at 500 m and 100 km.
**Warning signs:** the slot zippers only when the station is far; the hull shows through the faceplate; turning off log depth changes the pattern.

### Pitfall 3 — Custom shader missing log-depth or colour-space chunks

**What goes wrong:** the planet renders in front of the station/behind the sun; the planet is dark/oversaturated; the depth buffer disagrees with built-in materials.
**Why:** `ShaderMaterial` does not automatically include `logdepthbuf_*` or `colorspace_fragment`; Three only injects the `USE_LOGARITHMIC_DEPTH_BUFFER` define.
**How to avoid:** include `#include <common>`, `<logdepthbuf_pars_vertex>`, `<logdepthbuf_vertex>` in the vertex shader; `<logdepthbuf_pars_fragment>`, `<logdepthbuf_fragment>`, `<tonemapping_fragment>`, `<colorspace_fragment>` in the fragment shader. Add a unit test that reads the shader source string and asserts the chunk names, plus an e2e no-console-error check.
**Warning signs:** the planet is black at night; the sun draws over the planet; the station disappears behind the planet at long range; a shader compile warning in the console.

### Pitfall 4 — Treating `station_roll` as rad/s

**What goes wrong:** the station spins 36% too slowly (78.5 s/rev instead of 50 s/rev); launch roll looks wrong; Phase 4 docking timing is off.
**Why:** the config value is right-angles/s; Oolite's `setRoll:` multiplies by π/2.
**How to avoid:** `stationRollRadPerSec = stationRoll * Math.PI / 2`; test the value 0.125663706 and the 50 s period. Record the decision in PROJECT.md if the project intentionally chooses a different feel.
**Warning signs:** a test expects 0.08 rad/s; the station takes ~78 s per revolution; the launch roll and the station spin visibly disagree.

### Pitfall 5 — Normalising the authored station/sun vectors

**What goes wrong:** the station is 47 m closer to the planet and the sun 524 m closer than Oolite; layout goldens fail; the station/planet angular relationship is slightly off.
**Why:** `stationVector`/`sunVector` are not unit vectors in the pinned data; Oolite multiplies them as authored.
**How to avoid:** use raw vectors for positions; normalise only for directions (station orientation, nav buoy, lighting). Pin the actual distances 82,273.476 and 906,043.692 in tests.
**Warning signs:** a golden expects 82,320/905,520; the nav buoy is computed from a normalised vector but the station from a raw one (inconsistent).

### Pitfall 6 — Axis/sign conversion (dock, view offset, launch roll)

**What goes wrong:** the Coriolis dock faces away from the planet; the ship launches from the back of the station; the camera sits behind the Cobra’s tail; the launch slot counter-rotates at 2×.
**Why:** Phase 2 negates Z (`+Z` Oolite forward → `−Z` Three forward); the dock is at local −Z in the GLB; the view offset `(0,7.25,31)` becomes `(0,7.25,−31)`; the launch-roll sign after a reflection is not the same as Oolite’s `-flightRoll`.
**How to avoid:** map local −Z to `stationToPlanet` with `quatFromUnitVectors`; use `station + stationToPlanet*500.2561`; convert the view offset with the same `toWegolite`; verify the launch roll with a probe that measures the station’s relative roll over 1 s. Do not use `Object3D.lookAt()` for the station.
**Warning signs:** the planet is behind the station at launch; the Cobra exits from the station’s back; the camera looks out of the tail; the slot spins at double speed.

### Pitfall 7 — Using the wrong Cobra catalogue entry

**What goes wrong:** top speed 300 instead of 350, thrust 30 instead of 32, cargo 35 instead of 20; the flight feels sluggish and the HUD speed bar tops out at the wrong value.
**Why:** the catalogue contains `cobra3-trader` (300/30), `oolite_template_cobra3-alternate` (300/32, 35 t), and the player template (350/32, 20 t); `usable:false` on the template tempts a filter.
**How to avoid:** select `oolite_template_cobra3-player` by key, not by role/usable; assert 350/32/1/2/20/70 in a content test.
**Warning signs:** a speed test reaches 300; the max speed bar shows 0.300 LS; cargo capacity is 35.

### Pitfall 8 — Torus timestep, mass-lock overshoot, and target-speed blow-up

**What goes wrong:** at 1024× the ship moves 2,986 m per 1/120 step; it can pass through the station/planet if collision is added carelessly; mass-lock deceleration overshoots; the target speed keeps rising after disengage.
**Why:** speed is a scalar multiplied by a large factor; mass lock is a distance predicate evaluated per tick; deceleration uses the current factor.
**How to avoid:** mass-lock/refuse `j` before engaging; evaluate mass lock every tick; on mass-lock disengage, set `lastFactor` and decelerate at `thrustAccel × lastFactor × 3`; clamp speed to `maxSpeed × factor`; for Phase 4, add a swept collision or substep only near the station. Do not use a variable dt.
**Warning signs:** the ship jumps past the station under torus; speed stays at 20,000 after `j`; the factor is computed from the ship’s own radius; the torus engages while mass-locked.

### Pitfall 9 — Focus loss, stuck keys, and a clock that runs while hidden

**What goes wrong:** the ship spins after alt-tab; the clock advances while the tab is hidden; a keydown is missed and the ship keeps rolling; the pause overlay cannot be dismissed.
**Why:** browsers do not guarantee `keyup` after focus loss; RAF is throttled/stopped in background tabs; the accumulator can jump minutes.
**How to avoid:** on `blur`, `visibilitychange` hidden, `pointerlockchange`, `fullscreenchange`, pause and launch: clear the held-code set, set `paused=true`, reset the accumulator to 0; require a fresh keydown after resume; focus the pause overlay and return focus to the canvas. Clamp frame delta and cap steps.
**Warning signs:** the ship rotates while the window is unfocused; the clock jumps after returning; the pause button does not respond; held keys persist after reload.

### Pitfall 10 — HUD scaling blur, DPR mismatch, and letterbox drift

**What goes wrong:** HUD text is blurry on Retina; the scanner is stretched on ultrawide; the crosshair is off-centre; the HUD canvas is 2× the WebGL canvas.
**Why:** the canvas backing size and CSS size are conflated; `ctx.scale` is applied without DPR; the design-space transform is recomputed with a non-uniform scale; the canvas is resized to zero.
**How to avoid:** backing size = CSS size × min(dpr,2); CSS size = window size; `scale = min(backingW/1920, backingH/1080)`; centre with offsets; never non-uniformly stretch; guard zero dimensions; draw the break pattern with a reset transform at device pixels.
**Warning signs:** text has soft edges; the scanner is oval on 16:10 but not on 16:9; the crosshair drifts; the HUD canvas width ≠ `innerWidth*dpr`.

### Pitfall 11 — Scene disposal leaks or disposes shared assets

**What goes wrong:** repeated scene swaps grow `renderer.info.memory.geometries/textures`; the MenuScene’s Cobra disappears because `SystemScene.dispose()` disposed the shared GLB; textures leak because only materials are disposed.
**Why:** `Object3D.clone()` shares geometries/materials/textures; a blind `traverse(dispose)` hits cached assets; Three does not dispose textures when a material is disposed.
**How to avoid:** `AssetCache` owns shared GLBs/textures; `SystemScene` keeps a `disposables: {dispose():void}[]` for only its own resources; dispose materials and their maps explicitly; remove the scene root; call `renderer.renderLists.dispose()` after a swap; test 3 swaps for non-growth.
**Warning signs:** memory counts climb monotonically; the menu Cobra turns black after returning; the second system has missing textures; `renderer.info.programs.length` grows.

### Pitfall 12 — `ships.json` static import bloats the initial bundle

**What goes wrong:** the main JS chunk grows by ~700 KB raw; initial load slows; the 250 KB gzip budget is at risk.
**Why:** `ships.json` is 706 KB; a static JSON import retains the whole catalogue in the main chunk.
**How to avoid:** dynamic `import("./generated/ships.json")` with a module-level promise; show a “Loading Lave…” state; select only the two entries needed. If the payload becomes a problem, add a small build-time `player-ship.json` in a later phase (not Phase 3).
**Warning signs:** the main chunk includes the ship catalogue; the first paint waits on the full catalogue; the content manifest is validated but the ship load has no error path.

### Pitfall 13 — Planet shader world-space precision

**What goes wrong:** the planet’s noise/terminator crawls as the camera moves; the day/night line shimmers; the rim flickers at long range.
**Why:** computing world position in float32 at 452 km (3 cm ULP) and feeding it to noise; using absolute coordinates in the shader.
**How to avoid:** sample noise on `normalize(localPosition)` (object space), compute `uSunDir` on the CPU in float64 and pass a unit vector in object space; use `vViewDir` from the camera-relative world position, not absolute. Keep the planet mesh at the camera-relative position.
**Warning signs:** the terminator crawls when the ship moves; the noise pattern changes with camera distance; the shader uses `modelMatrix[3].xyz` in the noise.

### Pitfall 14 — WebGL2 failure caught too late

**What goes wrong:** a browser without WebGL2 shows a blank canvas and a console error; the app boots the menu/HUD with no renderer.
**Why:** `new WebGLRenderer` throws or returns a WebGL1 context; the current boot has no top-level catch.
**How to avoid:** wrap renderer creation/context verification in `try/catch`, show a DOM fallback before constructing scenes/HUD, publish `ready:false`, and do not start the RAF. Test by overriding `getContext('webgl2')` in Playwright.
**Warning signs:** blank page on Safari 14/Lockdown Mode; `__wegolite` is undefined; the HUD still draws over a dead canvas.

### Pitfall 15 — Headless SwiftShader mistaken for a real GPU

**What goes wrong:** the e2e suite passes under SwiftShader but the scene stutters on integrated GPUs; shader precision or log-depth artefacts appear only on real hardware.
**Why:** headless Chromium uses SwiftShader (software) by default; it is a correctness check, not a performance or precision guarantee.
**How to avoid:** keep numeric probes for correctness; add a manual real-GPU check (1080p, integrated graphics) for visual stability; do not add pixel diffs; keep the draw-call/triangle budget visible in the probe.
**Warning signs:** the probe reports a low frame count under SwiftShader; the manual check shows jitter/z-fighting; a shader compiles differently on the real GPU.

### Pitfall 16 — `localStorage` treated as trusted

**What goes wrong:** a tampered settings blob crashes boot, injects HTML, or creates prototype pollution; a huge bindings array freezes the UI.
**Why:** `localStorage` is attacker-controlled in the browser; `JSON.parse` + `Object.assign` is not validation.
**How to avoid:** validate against a strict schema with an action/hint allowlist, cap array lengths, build fresh `Object.create(null)` maps, never use `innerHTML` for messages/labels, catch quota/parse errors and back up the corrupt blob.
**Warning signs:** `JSON.parse` result is assigned directly; `innerHTML` appears in HUD/UI code; a 10,000-key settings object is accepted.

### Pitfall 17 — Coriolis/Cobra emissive textures blow out

**What goes wrong:** the whole station glows uniformly; the Cobra hull looks neon; the daytime planet is washed out.
**Why:** the GLB materials have `emissiveFactor [1,1,1]` and baked greyscale emissive maps; the Coriolis source `emission_modulate_color` values are in the thousands (normalised to ~26× in `extras`); Oolite relies on its shader/tonemapper.
**How to avoid:** tune `emissiveIntensity` at runtime (start 0.6–1.0 for the Coriolis, 0.5–0.8 for the Cobra Hull); keep `toneMapping = NoToneMapping` and `outputColorSpace = SRGB`; inspect the GLB material extras; do not assign the diffuse alpha as an emissive map at runtime (Phase 2 already baked a separate PNG).
**Warning signs:** the station is a white blob; the hull glows in shadow; the emissive map is the diffuse map.

### Pitfall 18 — Dust left behind at the old origin

**What goes wrong:** the speed cue disappears after a long flight; dust particles clump at a world origin; torus looks static.
**Why:** the dust geometry keeps absolute positions; the camera moves away; the box is not re-centred.
**How to avoid:** keep dust in camera-local coordinates, subtract the camera delta each frame, wrap each axis modulo the box size, and re-seed on a large teleport; no absolute positions in the geometry.
**Warning signs:** dust is visible at launch but gone after 10 km; particles form a wall at one coordinate; torus has no motion cue.

## Security Domain

> `security_enforcement` is enabled (absent from config = enabled). Phase 3 is a static, single-player client with no backend, accounts, or runtime network calls.

### Applicable ASVS Categories

| ASVS category | Applies | Standard control |
|---------------|---------|------------------|
| V2 Authentication | No | No accounts or login. |
| V3 Session Management | No | No sessions/cookies. |
| V4 Access Control | No | Single-player local state; no server resources. |
| V5 Input Validation | **Yes** | Validate the `localStorage` settings blob against a strict allowlist schema; cap array lengths; validate `KeyboardEvent.code` values; never `eval`/`new Function`; render all strings with `textContent`, never `innerHTML`; gate the `?test=1` hook. |
| V6 Cryptography | No | No cryptography. FNV-1a is an integrity checksum for golden tests, not a security control (`src/sim/hash.ts` says so). |

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard mitigation |
|---------|--------|---------------------|
| Stored XSS via a tampered `localStorage` settings/message string | Tampering / Elevation | Strict schema/allowlist, `textContent` only, no dynamic HTML, no `innerHTML` in HUD/UI. |
| Prototype pollution via settings keys (`__proto__`, `constructor`) | Tampering | Build fresh `Object.create(null)` maps; allowlist `ActionId`/`HintId`; never deep-merge arbitrary JSON. |
| Resource exhaustion via a huge bindings/hints array | Denial of service | Cap bindings per action (4), hint array (16), and string lengths; reject oversized blobs. |
| Test API abuse via `window.__wegolite.test` | Elevation | Expose only with `?test=1`; limit to scene swap/dispose/position/speed; no save mutation or arbitrary code. |
| Runtime network exfiltration | Information disclosure | No external fetches; assets are same-origin `public/`; e2e can assert no non-local requests during the loop. |
| Shader/resource denial of service | Denial of service | Static shaders, no user-supplied GLSL; cap star/dust counts; no unbounded per-frame allocation. |
| WebGL context loss / tab throttling | Denial of service | Phase 3 fallback for missing WebGL2; Phase 7 owns full context-loss recovery. Do not simulate hidden time. |
| Console error leakage | Information disclosure | No secrets in the client; keep console output to the existing content version line and development stats. |
