<objective>
Make the 3D projection match the canvas at every viewport shape by applying the aspect whenever a camera is installed, not only on `window.resize`.

Purpose: G-03-2. Every `PerspectiveCamera` is built with `aspect = 1`; the only writer is `main.ts`'s `resize()`, which runs at boot against the throwaway empty scene and afterwards only on `window.resize`. Entering the system installs a fresh aspect-1 camera and resizes only the HUD, so at 2222x1000 the entire 3D layer is stretched by 2.22 while the HUD stays circular — and any window resize silently repairs it, which is why the committed suite is green.

Output: `src/render/viewport.ts` (the single writer), `SceneManager` applying it on every install, `main.ts` delegating to it, a live `probe.aspect`, and `tests/e2e/aspect.spec.ts` plus Node tests that assert the projection matrix rather than the picture.

**Scope boundary:** no camera gets a new constructor argument and the render modules stay free of `window` access — the manager reads the renderer size it already holds. This is deliberate coverage for the two camera-artifact entries in G-03-2: `src/render/system-scene.ts` and `src/render/menu-scene.ts` keep constructing at `aspect = 1` and are **not** edited, because the manager is the single writer and both install paths are asserted (empty, menu, system, swap). Adding a second writer in the constructors is the failure mode this plan exists to remove. The HUD's Canvas2D scaling is a separate, already-correct path and is not touched.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| window/renderer size -> projection matrix | A degenerate size (0, negative, NaN) would write an Infinity aspect and break every later frame |
| scene install -> active camera | A camera created without a viewport silently renders at 1:1 and is invisible to unit tests unless asserted |
| `?test=1` swap -> projection | A rebuild path that forgets the viewport reintroduces the defect only after a swap |

**ASVS L1 relevance:** V5 (input validation) for the size guard; no network, storage or auth surface. The `?test=1` hook remains the plan-09 gated surface, unchanged.
