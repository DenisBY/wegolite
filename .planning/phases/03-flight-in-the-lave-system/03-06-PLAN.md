<objective>
Complete the control and persistence layer: a rebindable semantic action map, a strict versioned `localStorage` settings blob, and the single pause overlay that freezes the simulation and clears held input on focus loss.

Purpose: FLGT-06/07 are the requirements that make the game controllable and resumable, and they are also the phase's main untrusted-input surface. The settings blob is attacker-controlled in a browser, and a global key listener can both steal keystrokes and leave the ship spinning after alt-tab; this plan closes those edges with a strict schema and explicit capture scope.

Output: the final `src/input/` modules, `src/settings/schema.ts` + `store.ts`, the pause/controls/settings DOM panels, wiring in `game-session`/`main`/`index.html`, and `tests/settings/schema.test.ts`, `tests/input/bindings.test.ts`, `tests/e2e/settings.spec.ts`.

**Reversibility note:** the persisted settings key/schema (`wegolite.settings`, version 1) is graded `costly`, not `one-way`: a rename/migration can read the old key, but shipping it means every existing player has data under it, so a change needs a deliberate migration. It is flagged here and does not warrant a blocking decision checkpoint.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage -> settings | Browser-controlled JSON crosses into UI/input configuration |
| keyboard capture -> game | Global key listeners can capture keystrokes intended for text inputs or the browser |
| pause/blur -> simulation clock | Focus loss can otherwise let wall-clock time enter the accumulator |

**ASVS L1 relevance:** V5 (input validation) for the strict settings schema; V14 (configuration) for the capture scope and `preventDefault` rules — L1 only.
