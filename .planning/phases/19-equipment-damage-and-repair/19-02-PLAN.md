## Decisions this plan implements

- **D-01:** the gate loop, after the hit reaches the energy bank, on a seeded frame-rate-independent stream; the sim only emits events (the app commit is 19-10).
- **D-02:** `takeInternalDamage` as one die roll over `n_considered`, branches in order: cargo, equipment (die reversed), cosmetic.
- **D-04:** the cargo branch, ported, odds as Oolite's. "It goes through the same event and the same atomic profile update as equipment damage" is read as the same event path: both outcomes are sim events with one shared router row shape, one `damageFlow` subscriber and one `commitProfile` (19-10); the payloads differ, so they are two kinds (`equipmentDamaged`, `cargoDestroyed`). Flagged for the plan reviewers to confirm (Claude's discretion covers event names and payloads).
- **D-05:** `SHIP_TRADE_IN_FACTOR = 95`, constant, unpersisted; cosmetic branch not ported; Key Decisions row, todo, tripwire.
- **D-12:** the stream is a divergence from Oolite's global `ranrot_rand`, recorded as its own Key Decisions row here with the reviewers' agreement from the plan review `19-REVIEWS.md` in its `Reviewers:` field (the factor-95 row likewise); the FIDELITY rows that quote it are written in 19-14.
- **Claude's discretion:** the stream (stateless per tick, purpose 5); the pick order is `profile.equipment` order, which equals Oolite's `_equipment` insertion order (an `NSMutableArray`, `ShipEntity.h:447`; CONTEXT's "NSDictionary" is corrected by the research); `randf()` maps to `u`; the draw source is injected as `draw: () => number` so the hand tests can script exact draws.
- **Reversibility:** reversible: nothing in this plan is persisted or hashed.
