<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `shipdata.plist` keys and `like_ship` values -> resolved catalogue | A cycle, a dangling reference, or a mis-inherited flag changes what ships exist |
| resolved `model` value -> filesystem lookup | A plist value chooses a path |
| resolved `extras` -> downstream consumers | Raw third-party data is carried forward |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Denial of service / Tampering | `like-ship.ts` resolver | high | mitigate | DFS with an explicit visiting stack, memoisation, a 64-depth cap, `LIKE_SHIP_CYCLE` carrying the closed chain, and `LIKE_SHIP_DANGLING` for a missing target. A cycle can neither hang the build nor be silently dropped. The order-independence property proves the resolution is a join, not an iteration-order artefact. |
| T-02-16 | Tampering | `convert/ships.ts` `model` resolution | high | mitigate | Every model value is joined under `third_party/oolite/Models/` and asserted to stay inside it; `..` and absolute paths throw `DAT_MESH` naming the entry and attempted path. A hostile plist value cannot read outside the snapshot. |
