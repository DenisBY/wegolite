<objective>
Build the catalogue-growth seams the roster needs before it arrives: hull octrees shared per model through an optional `aliases` list, `hullTable` registering the aliases, and every hard-coded roster count in the hull, content and browser tests derived from the catalogue (DATA-18). On today's nine records nothing changes: the hull chunk is byte-identical and every derived count equals today's literal.

Purpose: 29 records sit on 18 models (plan 21-08); without sharing, the hull chunk would carry the same octree several times and pass `MAX_HULLS`, and every literal count would have to move in the roster plan. Landing the mechanism first keeps plan 21-08 within its file budget and makes its hull growth a data change only.
Output: the grouping converter, the schema field and repeat check, the alias-aware `hullTable`, the derived counts, and the remote verify and browser runs.

Tracer: Task 1 carries one synthetic two-key model through the converter's grouping, the strict schema, the generated-entry shape and `hullTable`, ending with both keys resolving to the same `HullData` object.
</objective>
