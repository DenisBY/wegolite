Network rule: AGENTS.md forbids fetching Oolite files over the network, but the owner sanctioned running `scripts/vendor-oolite.sh` (which fetches from `raw.githubusercontent.com` at `7437f22`) for this phase, on condition that every file is then cross-checked against `/home/opencode/git/oolite` and the result is confirmed at a `checkpoint:human-verify` (Task 3). Plan 09-05 Task 3 records it in `.planning/PROJECT.md` Key Decisions.

Host-run exception (owner-accepted, plan revision 2026-11-13; re-confirmed by the owner at Task 3): the cross-check script runs on the host shell, not in a container. Reason: the `wegolite-ci` image (`node:24-bookworm-slim` plus the Chromium libraries and `webp`) has `sha256sum` but no `git` (checked on 2026-11-13 with `docker run --rm --entrypoint sh wegolite-ci -c 'command -v git'`, which printed nothing), and the comparison against the pinned commit needs `git -C /home/opencode/git/oolite show 7437f22:<path>`; the checkout lives outside the repository. Adding `git` to the shared image for one provenance check would force an image rebuild and a node_modules volume reset on a slow machine. The script is read-only (it hashes; it writes only its report under `/tmp/wegolite-09-01/`), it is not a test or a build, and it never lives in the repository. Every test, build and gate of this plan still runs in Docker.
