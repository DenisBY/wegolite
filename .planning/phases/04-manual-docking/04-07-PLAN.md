  Per UAT G-04-3 and `.planning/debug/new-game-save-confirmation.md`.

  index.html:
  - Add one static confirmation overlay inside `#title-screen`, hidden by default. Give it `role="alertdialog"`, `aria-modal="true"`, `aria-labelledby` and `aria-describedby`. The text must state that the saved game will be permanently deleted and cannot be undone.
  - Provide exactly two controls: a safe Cancel button (`id="title-confirm-cancel"`) and a destructive accept button (`id="title-confirm-accept"`). Keep both as static markup with `type="button"`.
  - Add CSS for a centred panel over a dimmed backdrop, reusing the existing title-screen green/monospace palette. The global `[hidden]` rule already owns visibility.

  src/ui/title.ts:
  - Export `shouldConfirmNewGame(status: SaveStatus): boolean`, returning true exactly for `valid` and `corrupt`. Import `SaveStatus` as a type-only dependency.
  - Extend `TitleScreen` with `setNewGameConfirmationRequired(required: boolean): void`.
  - On a New game click: when the requirement is set and the player has not yet confirmed, show the overlay and focus Cancel (the safe action); otherwise invoke the existing start handler exactly once.
  - On accept: hide the overlay and invoke the start handler. On Cancel or Escape: hide the overlay and return focus to `#title-start` without invoking the handler.
  - Mirror `src/ui/pause.ts`: one `AbortController` for listeners, a Tab focus trap over the visible buttons, Escape cancellation, and focus restoration. Write every string through static markup or `textContent`; this module writes no dynamic text.
  - `setNewGameConfirmationRequired(false)` must leave the first-click path unchanged, so a fresh boot starts immediately.

  src/main.ts:
  - Import `shouldConfirmNewGame` and call `title.setNewGameConfirmationRequired(shouldConfirmNewGame(saveStatus))` before wiring `title.onStart`, using the `saveStatus` already derived from the boot read.
  - Do not change the `onStart` handler body: it still calls `session.start()`, which owns the committed clear.

  tests/app/title-confirm.test.ts:
  - Table-driven cases for all six statuses: `valid` and `corrupt` true; `absent`, `future`, `unreadable` and `unavailable` false. The test imports only the pure predicate, so the Node test environment needs no DOM.
