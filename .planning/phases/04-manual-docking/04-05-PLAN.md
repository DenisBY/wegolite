  Per D-13, D-14 and review findings 3, 4, 8 and the durability/lifecycle MEDIUMs.

  idb-store.ts: `IndexedDbSaveStore` opens lazily through one shared `openPromise` (DB "wegolite", version 1, object store "saves"). Serialize every operation on a single chained promise queue. Resolve a write only from the transaction's `oncomplete`; reject/settle from `onabort` and `onerror`. Read stores the JSON string, never a structured object. On `blocked`, settle the open as unavailable and close a late `onsuccess` so no connection leaks. On `VersionError` (an existing DB newer than v1), mark the store unavailable and keep serving from memory for the session — never remove or recreate a newer database. `dispose()` closes the connection; operations queued after disposal resolve as no-ops. Every failure path resolves read to an error, and parse treats it as absent; a write/clear failure is swallowed but reported in `WriteResult.reason`.

  boot: `main.ts` reads the store before showing the title, then calls `parseSave` with all three allow-lists supplied at the call site — equipment keys from `loadEquipment()`, system ids from the loaded galaxy 0 systems, station keys from the ship catalogue. Show `#title-continue` only for an ok save; keep `#title-start` labelled "New game". Store the boot `SaveStatus` on the session.

  Corrupt backup call site (explicit): when `parseSave(raw, allow)` returns `{ok:false, reason:"corrupt"}`, boot calls `await store.backupCorrupt(raw)` exactly once, best-effort (a rejection is swallowed and must not block the title), before showing the title. `absent`, `future-version` and a store read error do not call it. The raw string is never parsed again after the backup, and the backup key is never read back.

  Title: `onContinue(handler)`, `setContinueVisible(boolean)`, textContent/hidden only.

  New game: if the boot status is `future`, do not clear and do not start a write path for the session (start fresh in memory, `probe.save.skipReason = "future"`); otherwise `await store.clear(revision)` and wait for the committed result before `session.start({fresh:true})` resolves, so a reload after the button cannot resurrect the old blob. The e2e waits on `probe.save.status` rather than on the click.

  Autosave triggers: the `launched` event (post-+600 snapshot, system/station identity) and a successful purchase. Skip when the boot status is `future` or when `testTainted` is true, recording `probe.save.skipReason` ("future" or "tainted"). Increment a monotonic `revision` per queued write; never autosave on docking or on a computer dock.

  `probe.save = {status, writes, committed, revision, lastClock, continueVisible, skipReason, unavailable}`; `lastClock` updates only from a committed write.
