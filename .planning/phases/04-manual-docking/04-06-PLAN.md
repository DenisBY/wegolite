  Per UAT G-04-2 and the root cause in `.planning/debug/disabled-buy-control.md`.

  - Replace the bare `<dd class="docked-message" data-field="dockcomp-message"></dd>` that currently follows the docking-computer `dd`. Put the reason inside the docking-computer value cell: a `span` carrying `data-field="dockcomp-message"`, `id="dockcomp-message"`, and a dedicated class (for example `docked-reason`).   - Change `ACTION_LABELS.dockingComputer` to `"Docking computer"`; the chord is rendered from the binding, not baked into the label.

  src/input/keyboard.ts:
  - Import `SHIFT_REQUIRED_ACTIONS` from `actions.js` and delete the module-private `REQUIRES_SHIFT` declaration together with its JSDoc block.
  - Replace that rationale by extending the `/** The modifier state that decides a chord. */` JSDoc above `KeyModifiers`, so that interface stays documented rather than orphaned. Keep the Oolite `n_key_autodock` rationale and the D-11 / T-04-18 references, and drop the two claims this change falsifies: that the requirement is private to the keyboard layer, and that the rebinding display is unaffected.

  src/input/bindings.ts:
  - Add `chordLabel(action: ActionId, code: string): string` that returns the template literal `Shift+${codeLabel(code)}` when the action is in `SHIFT_REQUIRED_ACTIONS`, and `codeLabel(code)` otherwise.
  - Make `labelFor` map every code through `chordLabel(action, code)`, so the Controls row prints `Shift+C` and a rebind to another key prints `Shift+<key>`.

  src/ui/controls.ts:
  - Import `chordLabel` and use `chordLabel(action, code)` in the successful-rebind status message so the feedback names the chord, not only the raw key: rebinding the docking computer to `KeyK` reports `Docking computer bound to Shift+K.` Row text continues to come from `labelFor`.
