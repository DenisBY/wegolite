<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| F2 controls -> save/load actions | A keyboard action can write or replace the only save. |
| IndexedDB blob -> in-session load | A hostile blob is parsed while a live session exists. |
| loaded state -> scene/UI install | A partial install could leave the game inconsistent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-15 | Data loss | manual Save overwriting the only slot | high | mitigate | Save asks for confirmation before overwriting a committed save; the safe action takes focus; the same `autosave` key and revision queue are used; future/unreadable slots are refused. |
| T-06-16 | Data loss | failed in-session Load leaving a half-swapped session | high | mitigate | Parse/validate first, resolve and build the scene once, install state in one synchronous block with no early return; a failure shows copy and returns before any mutation. |
| T-06-17 | Tampering | save/load actions leaking into flight or station contexts | medium | mitigate | Dedicated `saveScreen` context; every action scoped to it; F2 gated on the live docked mode; the session revalidates state before opening; F2 reserved. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package-legitimacy gate + blocking human checkpoint for `[ASSUMED]`/`[SUS]` packages. This plan adds no package. |
</threat_model>
