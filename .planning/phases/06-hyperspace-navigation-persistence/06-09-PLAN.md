**As a** player, **I want to** trust the F2 overwrite prompt, **so that** a mouse Cancel cannot disable Save and a stray Enter cannot replace my only save.

Purpose: close verification gap G-3. The dialog's mouse Cancel only clears module-local state while the session keeps a separate pending flag, and Enter is globally bound to confirm, so Cancel can silently disable Save and Enter on the focused Cancel button can overwrite anyway.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mouse/keyboard -> overwrite dialog | A destructive confirmation can be dismissed or accepted by pointer or key |
| dialog state -> session save gate | A stale session flag can silently disable or bypass the prompt |
| save-screen actions -> one save slot | Save/Load/Up/Down can act behind the open dialog |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-26 | Data loss | mouse Cancel / mouse Accept | high | mitigate | One `isConfirming()` owner; both buttons resolve through `resolveConfirm`, clear the dialog and restore focus before invoking the handler. |
| T-06-27 | Data loss | Enter on focused Cancel | high | mitigate | Enter maps to `saveScreenActivate`, which follows the focused control; Y is the explicit confirm; a browser case asserts byte identity. |
| T-06-28 | Tampering | save-screen actions behind the dialog | medium | mitigate | Up/Down/Save/Load are ignored while confirming; only Confirm/Cancel/Return resolve the dialog. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no dependency and no package-manager change. |
</threat_model>
