## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IndexedDB -> boot parser | a forged or stale blob crosses into the strict parser |
| profile -> autosave -> reload | credits and cargo must be one atomic snapshot |
| `?test=1` -> profile -> save | a privileged mutation must never become durable |
| source tree -> sim bundle | a new economy file could reintroduce DOM/global RNG |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-14 | Tampering | over-capacity or huge forged cargo (41 t, 36 M grams, 18 entries) | high | mitigate | schema bounds, 17-entry cap, `holdPodsUsed <= capacityPodsFor` corruption, 32 KiB pre-parse cap and a browser over-capacity case |
| T-05-15 | Tampering | credits and cargo written separately, so a reload duplicates money | high | mitigate | one `snapshotForSave` per accepted action, one JSON write, one parse/restore path; the e2e asserts one commit per action and the same balance after reload |
| T-05-16 | Elevation | a `?test=1` credit/equipment mutation becomes durable | high | mitigate | taint flag set by every hook mutation; `autosave()` skips a tainted profile and publishes the reason; the station loop uses real UI actions, never the hook |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package is added or upgraded this phase; any future install needs the package-legitimacy gate and a blocking human checkpoint |
</threat_model>
