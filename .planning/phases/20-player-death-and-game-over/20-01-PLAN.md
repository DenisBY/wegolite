<objective>
The player can die in the simulation: one ledger record that empties the bank of a player in flight kills it on that tick through one function, `killPlayer`, the world freezes, and the tick emits one `playerDestroyed` that names the cause and the culprit (D-04). A lethal ram goes through the same path, with Oolite's inelastic reversal for the now `destroyable` player (D-11).

Purpose: this is the death commit the tripwire guard was built for. The guard fails on a new flight mode or a `playerDestroyed` producer while its marker survives, and D-11 requires the marker's removal in the commit that adds the death, so Task 1 is one atomic change across the files it lists; each edit is a few lines. The same commit replaces the retired guard's producer rule with a producer-scope guard for `playerDestroyed` (the single death path stays machine-checked), makes `snapshotForSave` refuse a dead state (DEATH-06: between this plan and 20-04 no latch exists, so no later commit may be able to save a dead player; Task 1 audits the autosave callers for that window and Task 3 pins the no-write outcome) and adds the CHANGELOG line for the breaking change. Tasks 2 and 3 restate the collision and laser pins that encoded "the player cannot die" and bring the full suite back to green.
Output: `src/sim/combat/death.ts`, the ledger's lethal check, the freeze, the collision change, the producer-scope guard, the `snapshotForSave` refusal and its caller audit, the save-controller no-write case, the CHANGELOG entry, the laser death scenarios, and the updated pins. The new lethal-ram scenarios and the ledger's lethal-boundary and internal-damage cases are 20-02 Task 2 (moved there for the context budget; nothing in this plan's suite depends on them).
