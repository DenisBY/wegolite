## Oracle fixture contract (shared with plan 14-02; identical text in both plans)

1. A fixture file is a JSON array of fixture objects. Plan 14-01 writes `tests/oracles/npc/fixtures/<group>.json`; plan 14-02 writes `tests/oracles/npc/pursuit/fixtures/<group>.json`. Fixture ids are kebab-case and unique across both trees.
2. A fixture object has exactly these keys (strict): `id`; `title`; `oolite` (non-empty array of citations `<path>:<a>-<b>`, path starting `src/Core/` or `Resources/`, lines at commit `7437f22`); `derivation` (prose: how every expected value was obtained); `dt` (exactly 1/120; 1/60 is allowed only when the id starts with `rate-`); `horizon` (integer ticks, 1 to 36000); `stats` `{ maxFlightSpeed, maxFlightRoll, maxFlightPitch, thrust, mass, forwardWeapon }` with `forwardWeapon` one of `EQ_WEAPON_NONE`, `EQ_WEAPON_PULSE_LASER`, `EQ_WEAPON_BEAM_LASER`, `EQ_WEAPON_MINING_LASER`, `EQ_WEAPON_MILITARY_LASER`; `self` `{ id (always 101), scanClass, radius, position, forward, up, right, speed, flightRoll, flightPitch, stickRoll, stickPitch, accuracy (resolved, -5 to 10), frustration, successFactor, pitchingOver, jink, behaviour, targetId, destination, desiredRange, desiredSpeed, ownerId, escortSlot }`; `bodies` (array of `{ id, kind ("ship", "player", "station", "planet", "sun" or "buoy"), scanClass, radius, mass, position, forward, up, right, speed, behaviour, targetId }`; the player is id 100, statics 1 to 5, other ships 102 and up); `motion` (`"static"`, or `"constant-velocity"`: at the start of every tick each body advances along its own forward by `speed * dt` and never rotates); `assign` (ordered ShipControl calls applied at tick 0, each `{ op, value }` with op `setTarget`, `setDestination`, `setDesiredRange`, `setDesiredSpeed` or `perform`; may be empty); `draws` (unit draws in [0, 1) in Oolite's call order; the consumer fails when the port consumes a different number); `checks` (non-empty array of `{ tick, field, expected, tolerance, note }`, tick 0 to horizon, tick 0 meaning after `assign` and before the first update); `events` (the exact ordered list of `{ tick, name }` the steering posts, names from the closed list `shipAchievedDesiredRange`, `shipNowFacingDestination`, `shipAIFrustrated`, `shipTargetLost`; an empty array asserts none).
3. Frame: every vector is in Oolite's world frame (a ship's forward is its local +Z; forward, up and right are unit, orthogonal within 1e-9, and right × up = forward). Wegolite's world is Oolite's with every z component negated (the content build's mirror); a consumer applies exactly that mapping and nothing else.
4. Tick semantics: tick k is the state after k native updates of self, each `processBehaviour:` followed by `applyAttitudeChanges:` and `applyThrust:` in the order of `ShipEntity.m:2485-2638`, with `delta_t = dt`. A proximity alert set at the end of tick k is read at tick k+1 (`Universe.m:6532-6609`, collisions after updates). A check at tick 0 may only name fields that a `perform*` method sets without a draw, the ship's stats or another body (`behaviour`, `frustration`, `desiredSpeed` for STOP_STILL); the effects that need one of those (performTumble's sticks, performAttack's desired range, performFlee's jink and evasive choice, `ShipEntityAI.m:350-480`) are checked at tick 1 or later, and their draws come first in `draws`, before the draws of the first update's behaviour.
5. Fields (closed list, Oolite variable semantics): `flightSpeed`, `flightRoll`, `flightPitch`, `stickRoll`, `stickPitch`, `desiredSpeed`, `desiredRange`, `frustration`, `successFactor`, `pitchingOver` (0 or 1), `accuracy`, `behaviour` (a BEHAVIOUR name without the prefix; tolerance 0), `targetId`, `proximityAlert` (id; tolerance 0), `rangeToDestination` (centre distance), `rangeToTarget` (`rangeToPrimaryTarget`, `ShipEntity.m:9718-9733`), `headingErrorDestination`, `headingErrorTarget` (radians between self's forward and the direction to the destination or the target centre), `positionX|Y|Z`, `forwardX|Y|Z`, `upX|Y|Z`, `jinkX|Y|Z`, `destinationX|Y|Z` (Oolite frame).
6. Tolerances: every check states one. A simulated value's tolerance is at least four times the reference's measured |float32 − float64| difference at that check plus 1e-9; a closed form's tolerance is stated beside its derivation; discrete fields use 0. A pose whose threshold decision flips between float32 and float64 inside the horizon is moved away from the threshold, never covered by a wider tolerance.
7. Random draw rule: each Oolite `randf()` consumes one unit draw u; each `ranrot_rand() % N` consumes one draw and yields `floor(u * N)`.
