<objective>
**As a** player whose jump hits a broken destination, **I want** the game to stop cleanly in the system I left, with my save untouched, **so that** a failed arrival can never leave me in a half-swapped world or overwrite my last good save.

Purpose: close Phase 6 WR-04, deferred to this phase as test-seam work (`06-VERIFICATION.md` lines 19 and 27-28): there is no browser negative control for a throw inside the destination build, because no injection point exists. D-18 fixes the seam's form: a constructor option consumed only by tests, never reachable from a URL. Today e2e boots through `src/main.ts`, which never constructs a session with test options, so this plan adds a compile-time switch: the shipped build compiles the read out entirely, and a separate test build, served only to Playwright, compiles it in.

Output: the session option and guarded throw, the gated read in main.ts, the two build configs, a second Playwright web server, and a spec with the browser negative control plus a scan proving the shipped bundle carries no seam.

Framing source: Phase 6 WR-04 and CONTEXT D-18. Requirement mapping: QUAL-05, because the control proves a failure leaves simulation and save state uncorrupted.

Dependencies: wave 2 after 07-01 (`vite.config.ts` plugin), 07-02 (`src/main.ts` and `src/app/game-session.ts` recovery edits) and 07-05 (the `inFlightSaveAt` fixture helper).

Cost note: every Playwright run now also builds the test bundle once (the second web server), adding one Vite build to each e2e invocation.
</objective>
