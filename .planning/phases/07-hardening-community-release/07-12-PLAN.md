<objective>
**As a** contributor changing the simulation, the economy, hyperspace or the save format, **I want** coverage thresholds that fail the unit run when untested code appears, **so that** a regression in the core rules cannot slip through unnoticed.

Purpose: QUAL-04, coverage half. The unit suite is broad, but there is no coverage tool and no thresholds. This plan adds `@vitest/coverage-v8@5.0.5` only after the owner checks the package (D-19; the legitimacy seam returned SUS, reason too-new, published 2026-11-02), and sets per-glob thresholds for src/sim, src/sim/economy, src/sim/hyperspace, src/persistence and src/content from the first measured baseline (D-19). `src/persistence/idb-store.ts` stays browser-only and `fake-indexeddb` is not added (D-20).

This plan was split out of plan 07-03 so that each plan stays within ten modified files. Plan 07-03 holds the golden save and route data; this plan depends on it so the measured baseline includes those tests.

Output: the coverage dependency, coverage configuration with measured thresholds, the coverage-enabled `test` script, and the updated container contract.

Framing source: QUAL-04 and CONTEXT D-19 and D-20.

Ordering: the plan runs in wave 2 because it edits `tests/contract/container-contract.test.ts`, which plan 07-01 also edits, and after plan 07-03 for the baseline. Plan 07-09 depends on this plan because both edit package.json and the container contract. The package-legitimacy rule requires the blocking-human check before any install, so that gate opens the plan (Task 1). The tracer (Task 2) is the first implementation task: it wires the provider, the coverage block, the `test` script and the contract pin end to end, gated on one measured glob. Task 3 expands the measured thresholds to the other four globs.
</objective>
