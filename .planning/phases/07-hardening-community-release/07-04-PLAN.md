<objective>
**As the** project owner deciding what "works on Firefox" means for 0.1.0, **I want** measured evidence of whether Firefox can render the game inside our container before the image layout changes, **so that** the cross-browser gate is built on a proven engine path, not an assumption.

Purpose: QUAL-02 and D-09. The CI image bakes Chromium only (research Critical Finding 4), and headless WebGL2 in Firefox on Debian 12 is unproven (research Pitfall 4, Mozilla bug 1375585). This plan adds a kept engine smoke spec, runs it on Playwright Firefox and WebKit in a scratch copy of the image, and puts the result in front of the owner at a decision checkpoint before plan 07-09 changes the Dockerfile and Compose layout, which D-09 rates costly.

Output: `tests/e2e/engine.spec.ts` (kept, runs on Chromium in `verify` and later on Firefox in `e2e-cross`), a spike result table in `07-04-SPIKE-RESULTS.md` and the SUMMARY, and the owner's decision.

Framing source: QUAL-02 and CONTEXT D-07, D-08 and D-09.

Browser claim conflict (recorded for the owner): ROADMAP Phase 7 success criterion 2 and REQUIREMENTS QUAL-02 say "Chrome, Firefox, and Safari". CONTEXT D-07 narrows the 0.1.0 claim to current stable Chrome and current stable Firefox and forbids naming Safari, WebKit or macOS as supported. This plan follows D-07. WebKit is probed only as engine evidence; any later use must be labelled "webkit (Playwright)" and never "Safari". The requirement and roadmap text are not edited here; plan 07-11 records the conflict in PROJECT.md Key Decisions.
</objective>
