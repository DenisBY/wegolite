<objective>
**As a** player, **I want** the whole loop - start a game, buy, launch, jump, dock, sell, save and come back - to be proven working in one run on the shipped build, with nothing phoning home and nothing logging errors, **so that** a release is known to play end to end rather than in pieces.

Purpose: QUAL-03 asks for one end-to-end test of new game, launch, trade, hyperspace, dock and save/load; QUAL-08 asks that the shipped build makes no runtime network calls and logs no console errors during the core loop. Each step already has its own spec, but nothing chains them (research requirement table). The chain cannot use the in-page test hook at save-relevant steps, because any hook mutation taints the profile and every save is then skipped (research Critical Finding 6, PROJECT.md Key Decisions row for the purchase autosave). D-21 allows an IndexedDB pose fixture for the dock step instead; this spec rewrites the game's own arrival blob to the Diso dock mouth, exactly as the Phase 6 trigger-matrix test does (`tests/e2e/autosave.spec.ts` lines 430-680). D-17 scopes the network guard: no request to another origin; same-origin static GETs (GLB, PNG, galaxy chunks) are allowed. The PROJECT.md record of D-17 is plan 07-11.

Journey order note: trading happens while docked, so the spec trades at Lave before launching and again at Diso after docking. Every step QUAL-03 names is covered.

Output: a shared guard helper and the journey spec.

Framing source: QUAL-03, QUAL-08 and CONTEXT D-17 and D-21.

Runtime: the Phase 6 trigger-matrix path, which this journey extends, already needs several minutes on SwiftShader (fly-away about 90-130 s, countdown up to 180 s); the journey is budgeted at 900 s times the wait scale and runs in `verify`.
</objective>
