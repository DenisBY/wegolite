## 2. Container & build config

### `Dockerfile` — container definition, build-config

**Analog:** reference scaffold (`/tmp/cprobe/Dockerfile`), not repo-tracked.

**Verified shape** (D-01, D-02, FOUND-04) — full reference file, 16 lines:

```dockerfile
# syntax=docker/dockerfile:1
FROM node:24-bookworm-slim@sha256:c86ecead9e55a5210ac1727de38a4ca840bf03dcaf34dc9749addbf383b1920c AS base
WORKDIR /app
ENV PLAYWRIGHT_BROWSERS_PATH=/ms-playwright \
    CI=1
COPY package.json package-lock.json ./

FROM base AS deps
RUN npm ci --no-audit --no-fund

FROM deps AS ci
RUN npx playwright install --with-deps chromium \
 && rm -rf /var/lib/apt/lists/*
COPY . .

FROM ci AS dev
```

**Conventions the planner must encode:**

- Pin the **index** digest (`sha256:c86ecead…920c`), not a per-arch manifest. Record in the plan that `docker buildx imagetools inspect node:24-bookworm-slim` is how it was obtained — do **not** let the executor substitute `latest` or a tag-only pin.
- `COPY package.json package-lock.json ./` is the cache boundary. Any `COPY . .` before `npm ci` destroys layer reuse; keep the order `base → deps → ci → dev`.
- `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright` must be set in `base` (before `ci`), so the browser install and every later stage/test agree on the path.
- `npx playwright install --with-deps chromium` at image-build time only. No browser download at test time (FOUND-04), no Playwright base image (D-02), no Alpine/musl.
- The `dev` stage in the reference is an **empty alias**. That is intentional and acceptable; source arrives by bind mount. If the planner adds `CMD`, it must be `npm run dev`, and it must not change the target that Compose selects.
- Add a comment recording the accepted posture: Chromium runs as root in-container, sandbox disabled, tests load only `localhost` content we serve (Pitfall 10).
- **Stage naming discrepancy to decide explicitly:** D-01 names targets `base → deps → dev, ci, preview`; the verified reference has **no `preview` stage** and Compose builds `target: ci` for every service. Either (a) keep `ci` and record the decision, or (b) add `FROM ci AS preview` as an alias. Do not invent a fourth distinct build.

### `compose.yaml` — orchestration, build-config

**Analog:** reference scaffold (`/tmp/cprobe/compose.yaml`), not repo-tracked (58 lines, all verified resolving).

**Core pattern — one YAML anchor, seven services, one named volume:**

```yaml
name: wegolite

x-workspace: &workspace
  build:
    context: .
    target: ci
  image: wegolite-ci
  init: true
  volumes:
    - .:/app
    - wegolite-node-modules:/app/node_modules

services:
  app:
    <<: *workspace
    ports:
      - "5173:5173"
    command: ["npm", "run", "dev"]

  preview:
    <<: *workspace
    ports:
      - "4173:4173"
    command: ["sh", "-lc", "npm run build && npm run preview"]

  # test / lint / typecheck: anchor + command only, no ports
  e2e:
    <<: *workspace
    ipc: host
    command: ["npm", "run", "test:e2e"]

  verify:
    <<: *workspace
    ipc: host
    command:
      - sh
      - -lc
      - >-
        npm run lint &&
        npm run typecheck &&
        npm run test &&
        npm run build &&
        npm run test:e2e

volumes:
  wegolite-node-modules:
```

**Non-negotiables (each maps to a verified failure mode):**

1. **Every** service carries the bind mount and the named `node_modules` volume — not just `app`/`preview`. Otherwise `docker compose run --rm verify` validates stale image content (Pitfall 1).
2. `verify` uses **one `sh -lc` with `&&`**. Never `set -e;` + semicolons, never `depends_on` fan-in (D-03; exit codes do not propagate).
3. `ipc: host` on `e2e` and `verify` only.
4. Ports published **only** for `app:5173` and `preview:4173`.
5. `preview` command rebuilds before serving (`npm run build && npm run preview`) — FOUND-02 says `up preview` serves the *production bundle*.
6. `init: true` on the anchor.
7. Named volume (D-04, locked). Document the refresh procedure next to it: after any `package.json`/`package-lock.json` change, `docker compose build` is **not** enough — `docker compose down --volumes` is required (Pitfall 2).

### `tsconfig.json` — TS config, build-config

**Analog:** reference scaffold `tsconfig.json` + `tsconfig.base.json`, not repo-tracked.

**Reference split** (`/tmp/cprobe/tsconfig.base.json:2-16`):

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "verbatimModuleSyntax": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "isolatedModules": true,
    "skipLibCheck": true,
    "noEmit": true
  }
}
```

and `tsconfig.json:1-15` adds `"lib": ["ES2022", "DOM", "DOM.Iterable"]`, `"types": ["node"]`, and `include: ["src/**/*.ts", "tests/**/*.ts", "*.config.ts", "eslint.config.js", "tools/**/*.ts"]`.

**Recommendation for the plan:** the research's single-file form (`01-RESEARCH.md` §Code Examples) is authoritative — one root `tsconfig.json` holding the compiler options + `lib`/`types`/`include`, and `tsconfig.sim.json` extending **it**. The scaffold's `tsconfig.base.json` split exists only to let `tsconfig.sim.json` avoid inheriting `lib`/`types`; extending `tsconfig.json` and overriding both keys achieves the same thing with one fewer file.

**Do not create `tsconfig.app.json`.** The reference scaffold has one (`/tmp/cprobe/tsconfig.app.json`, 4 lines) but **no script references it**. Copying it adds a third project that nothing checks.

**Conventions that follow from these flags:**

- Relative imports in TS source end in **`.js`** (`./step.js`, `./math.js`) because `moduleResolution: "bundler"` + `verbatimModuleSyntax` keep ESM specifiers literal. Every reference file does this; the executor must too.
- Type-only imports use `import type { ... }`.
- `noUncheckedIndexedAccess` makes `arr[i]` return `T | undefined`. The established pattern is an explicit guard or a documented cast at the indexed site (`SCRIPT[tick % SCRIPT.length] as InputFrame` in `/tmp/cprobe/src/sim/cadence.test.ts:15-16`). Prefer a guard where it is cheap.
- `include` must cover every linted file or ESLint's `projectService` errors on all of them (Pitfall 9). If `eslint.config.js` is listed in `include`, it must be reachable (allowJs) **or** handled via `allowDefaultProject` — not both in a way that produces the "included by allowDefaultProject but also found in the project service" error. Reference does: `include` names it, `allowDefaultProject` also names it. Pick one and verify `npx eslint .` from a clean tree.
- The root project carries the **DOM** lib and `types: ["node"]`; that is fine because purity is enforced by the second project + ESLint, not by the root project.

**Why each line exists:**

### `src/sim/hash.ts` — FNV-1a + canonical text, sim-core

**Analog:** reference scaffold (`/tmp/cprobe/src/sim/hash.ts`, 17 lines), not repo-tracked. Full file — this is the canonical pattern for D-11:

```ts
/** 32-bit FNV-1a. Constants: offset basis 2166136261, prime 16777619. */
export function fnv1a32(text: string): string {
  let h = 0x811c9dc5;
  for (let i = 0; i < text.length; i++) {
    h ^= text.charCodeAt(i) & 0xff;
    h = Math.imul(h, 0x01000193) >>> 0;
  }
  return h.toString(16).padStart(8, "0");
}

/** Canonical fixed-precision number text: no `-0`, finite only. */
export function canon(n: number, digits = 6): string {
  if (!Number.isFinite(n)) throw new Error(`non-finite value in state: ${String(n)}`);
  const r = Number(n.toFixed(digits));
  return (r === 0 ? 0 : r).toFixed(digits);
}
```

**Non-negotiable details:**

- `Math.imul` + `>>> 0` (not `*`), or the hash loses the low bits.
- `canon` **throws** on non-finite. `NaN.toFixed(6)` is the string `"NaN"`, which would produce a stable hash for a broken sim (Pitfall 7).
- Re-parse the `toFixed` output and map `-0` to `0` before formatting, or `-0.0000004` and `0` hash differently.
- `charCodeAt(i) & 0xff` keeps the byte stream ASCII-safe and engine-independent.
- No `node:crypto` (D-11). This is an integrity checksum, not a security control — say so in a comment.

### `src/sim/loop.ts` — accumulator driver, sim-core

**Analog:** reference scaffold (`/tmp/cprobe/src/sim/loop.ts`, 40 lines), not repo-tracked. Full file, and the single most important shape in the phase:

```ts
/**
 * Drive the accumulator with explicit frame deltas.
 * The input log is indexed by TICK (not by frame): a determinism harness must replay a
 * per-tick input log, otherwise the same log is chunked differently at each cadence.
 */
export function runToSteps(
  s: SimState,
  frames: readonly number[],
  inputAtTick: (tick: number) => InputFrame,
  targetSteps: number,
): LoopResult {
  let acc = 0, steps = 0, i = 0;
  while (steps < targetSteps) {
    const delta = Math.min(frames[i] ?? 0, MAX_FRAME_DELTA);
    i++;
    acc += delta;
    let n = 0;
    while (acc >= DT && n < MAX_STEPS_PER_FRAME && steps < targetSteps) {
      step(s, inputAtTick(s.tick), DT);
      acc -= DT;
      steps++;
      n++;
    }
    if (n === MAX_STEPS_PER_FRAME) acc = 0;
    if (i >= frames.length && steps < targetSteps) throw new Error("frame list exhausted");
  }
  return { frames: i, steps, accumulator: acc };
}
```

**Why it is shaped this way (measured, not theoretical):**

- **Stops on a tick count.** 1 s at 144 Hz yields 119 steps, not 120, because 1/144 does not divide 1/120. A time-based stopping condition fails a correct loop (Pitfall 5).
- **Input sampled per tick** inside the loop. Frame-indexed input produced four different hashes across four cadences (Pitfall 6). Add the comment distinguishing this replay contract from the interactive game's once-per-frame device sampling — otherwise `ARCHITECTURE.md:312` reads as a contradiction.
- Clamp each frame delta to `MAX_FRAME_DELTA`; drop the accumulator after `MAX_STEPS_PER_FRAME` (backlog reset). Resume with `acc = 0` (never replay hidden time).
- Throwing on frame-list exhaustion is deliberate: a silently short replay would hash a different state and look like a sim bug.

### `src/render/camera-relative.ts` — pure transform, render

**Analog:** reference scaffold (`/tmp/cprobe/src/render/camera-relative.ts`, 34 lines), not repo-tracked. Full file:

```ts
export interface Point3 { readonly x: number; readonly y: number; readonly z: number }
export interface Point3Out { x: number; y: number; z: number }

/**
 * The one place absolute sim coordinates become render coordinates.
 * Both operands are float64 (JS number); the subtraction happens before any float32 upload.
 */
export function cameraRelative(world: Point3, camera: Point3): Point3Out {
  return { x: world.x - camera.x, y: world.y - camera.y, z: world.z - camera.z };
}

/** float32 unit-in-the-last-place at magnitude x: 2^(floor(log2 x) - 23). */
export function f32Ulp(x: number): number {
  const m = Math.abs(x);
  if (m === 0) return Math.pow(2, -149);
  return Math.pow(2, Math.floor(Math.log2(m)) - 23);
}

/** How far a float64 value moves when rounded to float32. */
export function f32Error(x: number): number {
  return Math.abs(Math.fround(x) - x);
}
```

**Conventions:**

- Zero imports. This is what makes it testable in Node and gated by `tsconfig.sim.json` if the planner includes it there.
- The subtraction happens in JS doubles **before** any float32 boundary; no `Math.fround` in `cameraRelative` itself (`f32Error` exists to measure, not to apply).
- This is the only module allowed to turn world coordinates into render coordinates.
- Module-level doc comment states the invariant; the executor should keep it.

## 9. Shared patterns (apply across files)

### S-1 — Import zones and one-way data flow

```
shell (index.html, main.ts) ──► render ──► three
        │                         ▲
        └──► sim (pure TS) ───────┘   via cameraRelative only
```

- `sim/**` imports only `sim/**` and (later) `content/types`. No Three, no DOM, no wall clock, no `Math.random`.
- `render/**` may import `three` and `sim` value/type modules, never `app/**` or `ui/**`.
- `main.ts` is the composer: it owns the canvas, renderer, camera, and the single `place()` call site.
- Enforced by BOTH `tsconfig.sim.json` (DOM identifiers) and `eslint.config.js` (imports/properties). Neither alone is sufficient — verified in both directions.

### S-2 — Determinism discipline inside `src/sim/`

Every sim file carries the same header comment and obeys: no `Date`, no `performance.now()`, no `Math.random()`, no `setTimeout`, no DOM, no Three. `step()` receives `dt`; only `loop.ts` owns the accumulator; only `hash.ts` formats numbers for comparison.

### S-3 — Canonical serialization before hashing

Every numeric field → `canon(n, 6)` → labelled line → `fnv1a32`. Non-finite throws. `-0` normalises to `0`. Nothing else may stringify state.

### S-4 — Camera-relative upload

World positions are float64 metres and live in sim/render constants. Only `cameraRelative(world, camera)` produces values that reach `Object3D.position`. The camera sits at the origin. `logarithmicDepthBuffer: true`, never combined with `reversedDepthBuffer` (r187 silently disables log depth).

### S-5 — ESM + type-only import style

Relative imports end in `.js`; `import type` for types; `readonly` on value interfaces; no default exports except config files.

### S-6 — Source-file licence header

Every new `.ts` / `.js` file starts with:

```ts
// SPDX-License-Identifier: GPL-2.0-or-later
// Copyright (c) 2026 Wegolite contributors
```

This is the practical form of the FSF election requirement and keeps `NOTICE` and file headers consistent. Config files that Prettier reformats keep the comment at the top.

### S-7 — DOM text safety

Any overlay/status text is written with `textContent`, never `innerHTML` (security V7). The Phase 1 overlay is static, but the rule is established now for Phase 5.

### S-8 — Container-only execution

No host `npm`/`npx`. Every command in the plan is `docker compose …`. Dependency installs happen in the image build (`npm ci`), never on the host, never at test time.
