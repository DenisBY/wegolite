<objective>
Close UAT gap G-01-4 / review finding CR-01: resizing the browser window currently reallocates the WebGL drawing buffer and updates the camera but never repaints, so the canvas presents black until the page is reloaded.

Purpose: the Phase 1 walking skeleton is user-facing. A resize that blanks it is a real defect in the served shell, and Phase 3's render loop will mask it rather than fix it. This plan repaints once per resize event — with a zero-size guard — and adds the browser regression that would have caught it.

Output: a resize handler that renders after resizing, a monotonic `renders` counter on the existing probe, a new Playwright resize regression covering both the resize and the restore path, and CR-01 recorded as fixed in the review disposition.

Note on `depends_on`: all six prior plans are listed as scheduling dependencies because this plan's verification runs the whole-tree lint/typecheck/test/build/e2e chain. Functionally it builds on 01-01 (the shell and the one-shot boot render) and 01-04 (the probe and browser-test conventions).
</objective>

2. Add a module-scope `let renderCount = 0;` and a `renderFrame()` helper that: calls `renderer.render(scene, camera)`; increments `renderCount`; and, only when `window.__wegolite` has already been assigned, refreshes the probe's `calls` and `triangles` from `renderer.info.render` and sets `renders` to the new count. 3. Rewrite `resize()` so it reads `window.innerWidth` and `window.innerHeight`, returns immediately when either is `0` (a minimised or hidden window would otherwise compute an `Infinity` aspect and resize the drawing buffer to nothing), then calls `renderer.setSize(width, height, false)`, sets `camera.aspect` to the ratio, calls `camera.updateProjectionMatrix()`, and calls `renderFrame()` as its final statement. This is the missing link CR-01 identifies.

4. Delete the standalone boot render (`renderer.render(scene, camera)`) that currently follows `resize()`. The initial `resize()` call now performs the boot render, so removing the standalone call keeps exactly one render per resize event and no second frame at boot. Publish `renders: renderCount` in the `window.__wegolite` object literal; by then the boot `resize()` has rendered, so the probe reports 1 and `ready` still implies the numbers are real.

5. Do not add requestAnimationFrame, setAnimationLoop, an interval, a timer, a ResizeObserver, or any other ongoing drive. Do not add a context-loss handler in this plan. Do not alter renderer construction options, camera construction, `place()`, the scene, the status text, or the dev-only stats text.

6. Keep the S-6 SPDX header as the first two lines and keep the file Prettier-clean.
