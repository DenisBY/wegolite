## Phase 16 decisions this plan implements

- **D16-02 (vendoring from the local checkout):** `scripts/vendor-oolite.sh` gains two modes. `sh scripts/vendor-oolite.sh --export-pin <oolite-checkout> <out-dir>` runs on the host (needs only `sh`, `git`, `sha256sum`): it resolves `7437f22` to its full SHA, writes every `FILES` path's blob at that commit to `<out-dir>/Resources/<path>` with `git cat-file blob`, and writes `<out-dir>/pinned.sha256` (`# commit <full sha>` then `<hex>  <path>` lines). The container run with `OOLITE_LOCAL=<dir>/Resources` and `OOLITE_PINNED_SHA256=<dir>/pinned.sha256` copies each `FILES` path from the export instead of fetching, fails on a missing or mismatching pinned digest, and fails when any path already in the committed `CHECKSUMS.sha256` would change digest. The network mode is unchanged. Reversible: the modes are additive and the vendored bytes are content-addressed.
- **D16-07 / D16-08 (what is vendored):** only what is drawn: no scarred alloy texture, no fragment particle textures.
- **OC-7 (owner):** the real vendoring run is a human step (the script header's rule), see the Owner confirmation list.
