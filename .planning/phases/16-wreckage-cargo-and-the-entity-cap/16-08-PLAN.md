## Phase 16 decisions this plan implements

- **D16-10 (OC-2, rewords 15-CONTEXT D-03):** tumble stays a render-side cosmetic (D-03), derived from the contact's orientation and the flight time instead of the entity id, because no id may leave `src/sim`. `tumbleOrientation(q, info, t) = q x axisAngle(axis, |w| t)` with the constant local body rate `w = (info.maxFlightPitch x q.y, 0, info.maxFlightRoll x q.x)` (pitch about local x, roll about the local z nose axis), which stands for Oolite's `performTumble` rates drawn in `[-max, max]` (`ShipEntityAI.m:475-476`) since each component of a unit quaternion lies in `[-1, 1]`; a zero rate returns `q`. Two pieces with different orientations tumble differently, the same piece tumbles the same way every run.
- **D16-26 (recorded gap):** debris does not appear on the scanner (Oolite draws `CLASS_CARGO` on the scanner); `npcContacts` stays ships only and the scanner is unchanged. Deferred with scooping (CBT-11), where pods become something to fly to; recorded as a Key Decisions row by plan 16-09.
- **Lazy models:** the debris GLBs ride the existing per-session loader and its first-in-flight-frame latch (owner decision 2026-11-14, option A); no second loader and no new latch.
