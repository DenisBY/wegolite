# Quick task 261110-b7w: re-encode the ship textures as WebP

Executed inline by the main agent at the owner's request. Item P1 of
`.planning/reviews/2026-11-09-logic-security-review.md`. The owner allowed
recorded decisions to be revised where a better result justifies it; this task
revises Phase 2 D-20 ("copy the original PNGs verbatim").

## Why

`public/textures/` held 19.7 MB of PNG, almost the whole 20 MiB cold start.

## Tasks

1. Bake `cwebp` into the `ci` image (`webp` package from the pinned base).
2. Add `convert/texture-encode.ts`: pick a profile per file from the material
   slots that reference it, run `cwebp`, validate the output header against
   the source size and the profile, and emit `texture-encodings.json`.
   Re-use a committed output when its source hash and arguments are unchanged.
3. Emit WebP image URIs from the GLB writer through `EXT_texture_webp`, listed
   as required; emissive bakes keep a core PNG `source`.
4. Replace the byte-copy step in `generate.ts`; add `--reencode` to the CLI.
5. Tests: profiles and arguments, the committed files decoded with `dwebp`
   against their sources, the record, the re-use rule, failure paths, the GLB
   references, and the browser fetch of every image.
6. Provenance and docs: `ASSETS.md`, `NOTICE`, `README.md`,
   `docs/PERFORMANCE.md`, `CHANGELOG.md`, the first-load ceiling, and the
   PROJECT.md Key Decisions row.

## Verification

`typecheck`, `lint`, `assets:check`, the unit suite, a before/after screenshot
comparison of the Cobra and the Coriolis, and the Chromium browser suite.
