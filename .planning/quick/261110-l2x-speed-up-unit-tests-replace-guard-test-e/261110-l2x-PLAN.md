# Quick task 261110-l2x: speed up the unit-test loop

Executed inline by the main agent at the owner's request, on a dedicated branch
(`perf/unit-test-loop` off `main`).

## Goal and why

Recommendations 3 and 4 of the 2026-11-10 test-speed review. The four
`tests/guards/` files prove the architecture zones by writing a transient probe
file and spawning `npx eslint <probe>` for each case. Seventeen such spawns,
plus five `tsc -p tsconfig.sim.json --noEmit` spawns, are serialised by
`withProbeLock`. Each CLI call rebuilds a type-aware ESLint program at about
3.9 s, so the guard tests alone accounted for roughly 62 s of a 78.7 s
coverage-free run.

A scratch spike inside the container established that a single `ESLint`
instance keeps its TypeScript program across 17 created-and-deleted probe files
(first `lintText` 3.5 s, the rest 60–117 ms, 4.7 s total). A second spike
confirmed the Node API yields exactly the expected `ruleId`, custom message
text and `messageId`, so the existing assertions do not become vacuous.

## Locked design contract

- `npm test` stays `vitest run --coverage`; the D-19 per-glob thresholds stay.
- The `verify` and `verify-full` fail-fast chains are untouched, and no new
  Compose service, npm dependency or `src/sim` change is introduced.
- All 28 guard tests, their timeouts and every regex/message assertion survive.
- The five `tsc` spawns stay; this task replaces ESLint subprocesses only.
- `test:fast` is a local convenience, never a gate.
- No e2e, Playwright, Firefox or coverage configuration changes.

## Tasks

### Task 1: Prove the shared-program assumption

Scratch scripts under `/tmp/opencode/wegolite-bench/`, copied into the
container's named volume and removed afterwards; no repository files. Confirm
program reuse across transient probes and confirm the zone diagnostics.

### Task 2: Add the shared gate helper

Create `tests/guards/eslint-gate.ts` with the SPDX header. One module-level
`ESLint` instance per Vitest worker, `lintText()` against the absolute probe
path, and a `GateRun` carrying status, a synthesised `output` (rule id plus
message) and flat structured `messages`. Status is `1` when any result has
`errorCount > 0`, matching the CLI without `--max-warnings`.

### Task 3: Make the probe lock span an async lint

Convert `withProbeLock` to `async` and `return await body()` inside the `try`,
so the lock is released only after the awaited lint settles. Keep the stale
lock, timeout and `Atomics.wait` sleep logic unchanged.

### Task 4: Migrate the three linting guard files

`tools-determinism`, `content-boundary` and `sim-purity` import `lintProbe`;
remove their local `runGate("npx", ["eslint", ...])` and `--format json`
parsing. Make the affected tests and `withProbe` helpers async. Keep `runGate`
only for the `tsc` spawns. `economy-purity` is a pure source scan and is not
touched.

### Task 5: Add the local script and document it

Add `"test:fast": "vitest run"` to `package.json`, a row to the command tables
in `AGENTS.md` and `README.md`, an operational note in `README.md`, entries in
`CHANGELOG.md` under `## [Unreleased]`, and a Key Decisions row in
`.planning/PROJECT.md`.

### Task 6: Harden the positive control

Following an external review, assert `lint.messages` is empty in the
`the safe Math surface passes lint` case, so an ignored probe cannot make the
test pass vacuously.

## Verification

All commands run in Docker only, strictly sequentially (never `lint` in
parallel with `test`, because guard tests create transient probe files):

- `docker compose run --rm typecheck` — both `tsc` invocations clean.
- `docker compose run --rm test` — 103 files, 1366 passed, 1 skipped, all D-19
  thresholds satisfied.
- `docker compose run --rm test npm run test:fast` — same suite without coverage.
- `docker compose run --rm lint` — `eslint .` plus `prettier --check .` clean.
- `docker compose run --rm verify` — full fast gate end to end.
- `npx vitest run tests/guards --reporter=verbose` — 4 files, 28 tests.
