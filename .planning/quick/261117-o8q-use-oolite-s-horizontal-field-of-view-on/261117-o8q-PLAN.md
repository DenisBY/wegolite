Purpose: the size of every ship, station and planet on screen is a first-order fidelity property. Oolite's rule, verified in the local checkout (`/home/opencode/git/oolite`, and at the pin with `git show 7437f22:<path>`):
- `MyOpenGLView.m:1282-1290`: `_fov` is stored as the tangent of the half angle, `tan(value/2)`; `Universe.m:755` sets it from the `fov-value` preference, default 57.2, clamped to `MIN_FOV_DEG` 30 and `MAX_FOV_DEG` 80 (`MyOpenGLView.h:36-37`).
- `Universe.m:4385`: `aspect = height / width` (the inverse of Three's `camera.aspect`).
- `Universe.m:4445`: `ratio = (displayGUI ? 0.5 : fov) * near / distanceFactor`; the near plane is `near / distanceFactor`, so the factor cancels and only `ratio` shapes the angles.
- `Universe.m:4448-4452`: with `displayGUI` NO (flight) and `4 * aspect <= 3` (wider than or equal to 4:3), the frustum is `±ratio` in x and `±aspect * ratio` in y, so 57.2° spans the width. Otherwise (narrower than 4:3) it is `±3 * ratio / aspect / 4` in x and `±3 * ratio / 4` in y, so the vertical half-angle tangent stays at 0.75 x fov, the value it has at 4:3. With `displayGUI` YES the two branches swap: ratio 0.5 across the width when narrower than or equal to 4:3, and a vertical 0.375 when wider. Both branches meet at exactly 4:3 in both modes.
- `Universe.m:2987`: the intro Cobra screen sets `displayGUI = YES`, so Oolite draws its title Cobra through the GUI branch.
- `HeadUpDisplay.m:4002-4006`: the scanner's forward-view lines use `tanfov = fov`, multiplied by `0.75 * width / height` when narrower than 4:3, which is the flight frustum's horizontal half-angle tangent.

In Three.js terms, with A = width / height and f = tan(28.6°) ≈ 0.5452177: flight tangents are x = f, y = f / A when A >= 4/3, else y = 0.75 f, x = 0.75 f A; GUI tangents are x = 0.5, y = 0.5 / A when A <= 4/3, else y = 0.375, x = 0.375 A; `camera.fov` = 2 atan(y) in degrees. Reference values: 1280x720 flight fov 34.1000°, GUI 41.1121°; 4:3 flight 44.4806°; 1:1 flight 44.4806°, GUI 53.1301°; 1600x1000 flight 37.6342°.
