<objective>
Add a clickable tab strip to the docked station computer, with one tab per Oolite F-key in key order: Home | F1 Launch | F2 Save/Load | F3 Outfitting | F4 Interfaces | F5 Status | F6 Chart | F7 System data | F8 Market. The same registry-hydrated strip is rendered into the station shell (#docked) and into the F6 chart and F2 Save/Load overlays that cover it. F4 Interfaces becomes a live screen that shows Oolite's empty-state text.

Purpose: players who use the mouse can move between station screens without remembering F-keys, and every screen advertises the key that reaches it. The strip and the Home screen are deliberate Wegolite additions (Oolite has neither). The keyboard layer stays authoritative: the strip adds a pointer route into the same open paths and never a second behaviour.

Output: a pure tab registry, a DOM hydrator, one navigateStation sink in the session, F4 plumbing, nav markup and CSS in three surfaces, unit and browser tests, a README row and a PROJECT.md Key Decisions entry.

Decomposition note: the work is grouped by seam under the three-task cap. Task 1 is the pure and input-layer contract (everything the DOM and session consume, plus the README row that a contract test pins to the new action). Task 2 is the first end-to-end click path (hydrator, session sink, markup, CSS, fast-gate smoke). Task 3 is the full browser proof and the decision record. Task 1 touches many files because four of them are one-line or comment-only edits and the F4 action, its README row and its contract test must land in one commit.
</objective>
