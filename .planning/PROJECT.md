# Wegolite

## What This Is

Wegolite is a browser-based reimplementation of Oolite's core single-player experience — the open-source Elite clone. Players fly a Cobra Mk III out of a Coriolis station, dock manually, trade commodities between star systems, and improve their ship, all inside a desktop web browser with no install. It is an open-source fan project for the Oolite/Elite community. The long-term goal is to port all of Oolite's single-player functionality, and possibly add Wegolite's own features; expansion packs (OXPs) are out of scope for now.

## Core Value

A player can launch, fly, dock, and complete a profitable trade run between two star systems entirely in the browser — faithful to Oolite's rules, data, and feel.

## Current State

**Shipped:** v1.0 Core Loop (Phases 1-7, released as `v0.1.0` on 2026-11-08) and v2.0 Foundation (Phase 8, completed 2026-11-13; not yet in a tagged release, the latest release is `v0.3.0`).

v2.0 changed nothing the player sees. The game plays exactly as v1 does, but `src/app/game-session.ts` is split into typed controllers behind a 532-line facade, and the simulation runs a multi-entity world: stable per-world ids, seeded per-entity streams, a world hash, restorable test snapshots, a typed `WorldView`/`ShipControl` AI seam with a scripted test pilot, and a tick-stepping test hook (`advanceTicks`, `worldHash`, `probe.sim`). The AI seam, the snapshot codec and the reserved SimEvent types have only the test pilot as a consumer, so they stay provisional until Phases 12-14 exercise them.

## Current Milestone: v2.1 World Population Base

**Goal:** The world can hold real NPC ships: compiled from Oolite's data, given Oolite's mass, regenerated from the save's seed rather than saved, populated deterministically on arrival, and counted by mass lock and jump blockage. No NPC flight, AI or combat yet.

**Scope rule:** the necessary technical minimum, not player-visible features (owner, 2026-11-13: "less, but better"). Each phase is trimmed to what Phase 12 consumes; phase numbers 9-12 are kept from the former v2.1 plan so existing references stay valid.

**Target features:**
- Phase 9, NPC content: models, textures and combat stats of the NPC ships compiled from the pinned Oolite snapshot with provenance, lazily loaded outside the first load. Sounds and music (DATA-12) are deferred to the audio phase.
- Phase 10, ship mass: build-time hull octrees and Oolite's mass (`density * 20 * octree volume`), with the Coriolis mass checked against 455,223,200. Runtime ray and hull queries are deferred to the combat phase.
- Phase 11, minimal save schema v3: only the world epoch, the world counters and the next entity id, with leg-anchor semantics and an ordered v1 → v2 → v3 migration. Combat and law fields get their own later bumps.
- Phase 12, inert ships and the world lifecycle: inert NPC ships drawn and on the scanner within budget, mass lock and jump blockage by ships, the world running behind the chart, cleared at jump commit and repopulated deterministically on arrival, and a reload that regenerates the same world. Its first plan contains a throwing AI module (review WR-01) and makes `spawnEntity` refuse malformed input instead of throwing (IN-02).

**Deferred (unscheduled backlog, numbers unchanged):** Phases 13-23 of the former v2.1 Combat & Traffic plan: lasers and views, NPC flight and the AI fidelity gate, destruction and death, bounties and the escape pod, audio, priority AI and role traffic, police and law, pirates, missiles, full traffic and mining, and performance hardening with QUAL-01. Their requirements stay in `.planning/milestones/v2.0-REQUIREMENTS.md`.

## Context

**The source game.** Oolite is written in Objective-C (with some C/C++) on GNUstep + SDL + OpenGL, spanning roughly 515 source files. It ships its own JavaScript engine for world scripts, which is why its gameplay logic maps cleanly onto TypeScript. It is licensed GPL-2.0-or-later, and its art, sound, and configuration files are additionally available under CC BY-NC-SA 3.0.

**Reusable data.** `Resources/Config/` holds the canonical plists: `shipdata.plist`, `trade-goods.plist`, `equipment.plist`, `world-scripts.plist`, plus `planetinfo.plist` with all 2,048 systems across the eight galaxies. These are the source of truth for faithful numbers.

**Prior art worth studying.** Oolite's docking approach, flight model constants, commodity price formula, and hyperspace distance rules are documented on the Oolite wiki and in the source. Port mechanics from documented behavior; port numbers from the config files.

**Why the browser.** The goal is zero-install access for fans on any modern desktop machine. A static site with WebGL2 is the lowest-friction delivery mechanism.

**Codebase at v2.0 close (2026-11-13).** About 32,000 lines of TypeScript in `src/` and 51,000 in `tests/`; 2,407 unit tests and 128 Chromium browser specs green under `verify-full`. Known debt carried into v2.1: review WR-01 (a throwing AI module is not contained by the world step), intermittent e2e flakes under host load (Phase 8 deferred item D-2, plus `hyperspace.spec.ts:194` and the probe-shape in-flight state), `08-VALIDATION.md` still a draft, and 19 older open items acknowledged at the v2.0 close (see the Deferred Items table in `STATE.md`).

**Container-first development.** Every process in the project — dev server, production preview, unit tests, and browser tests — runs in Docker. The host machine is only expected to provide Docker and a browser; no host Node/npm install is authoritative. Because the client is static and saves live in IndexedDB, no database service is required. If server-side persistence is ever added, it gets its own Compose service with a healthcheck rather than a host install.

## Constraints

- **License**: GPL-2.0-or-later — chosen because the project ports Oolite's data and may port logic; mismatched licensing would make distribution indefensible.
- **Assets**: CC BY-NC-SA 3.0 — reused models, textures, and audio require attribution, share-alike, and forbid commercial use.
- **Tech stack**: TypeScript, Three.js on WebGL2, Vite for building, Vitest for unit tests. No game engine, no framework-level abstraction over the simulation.
- **Platform**: Desktop browsers (current stable Chrome and current stable Firefox) served as a static site. No backend, no accounts, no network calls at runtime. No database.
- **Containers**: The application (dev server and production preview) and the entire test suite run in Docker via Docker Compose. This includes headless browser tests — the image must ship the browsers, not download them on the host. Tests are only considered passing when they pass in the container. Host-side `npm test` is a convenience at most and never the source of truth.
- **Container reproducibility**: Compose must work from a clean checkout with one command, pin base images, and cache dependency layers. No service may require a manually installed host dependency beyond Docker itself.
- **Data fidelity**: System, commodity, equipment, and ship values come from Oolite's config, not from invention. Where the original is ambiguous, prefer documented Oolite behavior over guesswork.
- **Scope**: No expansion pack support for now. Revised at v2.0 from "Ever": the owner's long-term goal is to port all Oolite functionality, so OXP support may be reconsidered in a later milestone through an explicit decision.
